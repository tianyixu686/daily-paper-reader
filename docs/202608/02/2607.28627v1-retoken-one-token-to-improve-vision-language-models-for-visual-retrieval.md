## 摘要
长视觉上下文对视觉语言模型构成挑战：随着干扰物数量的增加，性能下降，且在GPU内存限制下，一次性处理所有令牌在计算上不可行。我们提出ReToken，一个可学习的单一嵌入，作为显式检索目标进行训练，从预填充的视觉KV缓存中选择一组与查询相关的稀疏视觉令牌。仅在小型图像问答数据集上训练，ReToken在图像和视频基准测试中均取得一致的提升：在Visual Haystacks上，它使Qwen3VL-8B提升13.4个百分点，InternVL3.5提升12.4个百分点（相对提升>20%），在LVBench上，它零样本迁移到长视频，为Qwen3VL-8B带来8.0个百分点的提升。得益于其轻量级设计，训练和长视频推理均可单张H100完成。代码可在：https://github.com/avaxiao/ReToken 获取。

## Abstract
Long visual context poses a challenge for vision-language models: performance degrades as the number of distractors grows, and processing all tokens at once is computationally infeasible under GPU memory constraints. We present ReToken, a single learnable embedding trained as an explicit retrieval target that selects a sparse set of query-relevant visual tokens from a pre-filled visual KV cache. Trained on only a small image-QA dataset, ReToken yields consistent gains across image and video benchmarks: on Visual Haystacks it improves Qwen3VL-8B by 13.4 points and InternVL3.5 by 12.4 points (>20% relative), and on LVBench it transfers zero-shot to long video for an 8.0-point gain with Qwen3VL-8B. Thanks to its lightweight design, both training and long-video inference fit on a single H100. Code is available at: https://github.com/avaxiao/ReToken

## 1. 核心问题与整体含义

- **研究动机**：长视觉上下文（如多图像集合、小时级视频）已进入VLM的输入范围，但VLM在面对大量干扰项时性能显著退化，且全量token处理在GPU内存限制下不可行。
- **核心问题**：长视觉输入处理可归结为检索问题——从海量视觉令牌中选取能够支撑正确答案的稀疏子集。现有基于注意力权重的检索信号在VLM中并不可靠。
- **关键发现**：注意力（Query-Key）得分不能有效区分相关与不相关帧；相比之下，**Value空间**携带更强的文本对齐检索信号——通过精确目标短语匹配平均value向量，在两个骨干上均显著优于Query-Key检索。
- **整体意义**：提出了ReToken——一个轻量级可学习检索令牌，仅需在小型图像QA数据集上训练，就能在图像和长视频基准上取得一致提升，且训练和推理均可在单张H100上完成，为长上下文多模态推理提供了实用路径。

## 2. 方法论

### 核心思想
- 与常见的Q-K注意力检索不同，ReToken利用**最后层视觉value向量**作为检索空间；将单个可学习嵌入（ReToken）附加到问题后，训练它作为显式检索目标。
- 仅需一个token + 一个投影矩阵（外加可学习logit温度），VLM默认完全冻结。

### 检索得分公式
- 每帧的检索得分为投影后的ReToken与帧平均value向量（最后层）的余弦相似度：
  - \bar{v}_f = 帧f内视觉token的value均值
  - Z_r = W_r X_r（投影）
  - s_f = cos(Z_r, \bar{v}_f)

### 训练损失
- 类别平衡的二元交叉熵（正负样本分别平均，避免负样本主导）：
  - L_ret = -（正类log-sigmoid平均）-（负类log-sigmoid平均）
- 可选部分微调VLM前1-3层时，额外加入生成损失L_gen（标准下一token预测），L = L_ret + λ·L_gen。

### 两遍推理流程
1. **视频编码一遍**：分块编码（sliding-window attention）构建持久化视觉KV缓存，旧KV可卸载到CPU。
2. **第一遍（检索）**：将ReToken附加到问题上，最终层计算每帧得分，得到Top-K集合S_K。
3. **第二遍（生成）**：仅加载S_K对应的KV缓存生成答案。
- 长视频下，早期层ReToken注意力被限制到Top-K1=256帧以控制内存。

## 6. 主要结论与发现

- **VHs上**：C=50时Qwen3VL-8B提升13.4点（58.6→72.0），InternVL3.5提升12.4点（57.3→69.7），相对提升>20%；C=100仍保持12.0点提升。
- **零样本视频迁移**：LVBench提升8.0点（40.6→48.6），Video-MME长视频分档提升3.4点。
- **QAEgo4D**：K=1时6.8点提升；K=16/32时分别增益6.4/5.4点，且Recall远高于均匀采样和ReKV。
- **价值空间优势**：Value-based检索明显优于Key-based；精确目标短语（而非完整问句）对value空间检索至关重要。
- **部分微调前3层**使KV缓存更干净（更少来自干扰图的污染），图像任务进一步提升，但会导致视频任务域偏移而下降。

## 7. 优点

- **极简设计**：仅一个可学习token + 投影矩阵，VLM冻结，参数开销极小。
- **诊断扎实**：通过系统的对照实验（问题句 vs 目标短语、Key vs Value）诊断出注意力检索失败的根因，发现value空间的优势。
- **零样本迁移**：仅用图像数据训练，视频任务上直接迁移有效，证明方法的泛化潜力。
- **资源友好**：单卡H100可完成训练和推理；KV缓存一遍编码、多问题共享。
- **检索精准性高**：在K=1的极紧检索预算下依然有效，与注意力检索（需较大K）形成鲜明对比。

## 8. 不足与局限

- **两遍推理开销**：需要两次前向传递，每问题约增加0.4秒延迟，且早期层需attend到更多视觉上下文（K1=256），增加少量内存负担。
- **训练数据单一**：仅使用图像QA数据，未利用视频数据；在需要时序结构/跨帧推理的任务（如时序定位、事件理解、总结）上增益有限甚至为负（summarization为-5.2点）。
- **帧级独立打分限制**：无法处理跨帧组合信息、时间偏移查询（“进入房间前发生了什么”）；帧级均值池化可能稀释仅占少量token的证据。
- **部分微调导致域偏移**：图像数据上微调VLM层会在视频任务上造成性能下降，限制了部分微调的实用价值。
- **InternVL3.5训练不足**：仅训练1 epoch导致在C=100时提升有限（+4.4点），说明训练预算对效果的约束。
- **多token未显优势**：3 token与1 token性能持平，缺少促使token专业化的机制。
