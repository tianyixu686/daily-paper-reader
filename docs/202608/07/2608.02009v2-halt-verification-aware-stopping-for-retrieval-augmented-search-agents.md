## 摘要
检索增强的搜索代理通过反复发出搜索查询并累积证据来回答多跳问题。这产生了一个停止问题：在必要证据出现后，进一步检索往往只会增加成本、延迟和分散注意力的上下文，而非有用信息。我们将停止问题定义为证据覆盖而非生成器置信度，并引入HALT——一种轻量级、验证感知的策略，它不改变搜索代理本身。给定预期的跳数声明，HALT仅在累积证据支持每个所需声明时停止。在三个多跳问答基准测试中，HALT在基本保持精确匹配的同时减少了冗余搜索。我们区分了可部署设置（其中跳数声明由问题生成）与使用黄金支持事实注释的诊断性上界：生成的声明带来的节省较小但仍保持精确匹配，而黄金声明则显示出当跳数目标清晰时可实现的更大节省。基线和消融实验表明，这种行为是由声明-证据对齐驱动的，而非通用的充分性、固定停止位置或词汇重叠。开放语料库试点进一步表明，当覆盖无法可靠验证时，HALT会弃权。总体而言，证据覆盖为改进检索增强代理提供了一种实用的运行时控制信号，无需重新训练或修改宿主代理。

## Abstract
Retrieval-augmented search agents answer multi-hop questions by repeatedly issuing search queries and accumulating evidence. This creates a stopping problem: after the necessary evidence has appeared, further retrieval often adds cost, latency, and distracting context rather than useful information. We frame stopping as evidence coverage rather than generator confidence, and introduce HALT, a lightweight verification-aware policy that leaves the search agent unchanged. Given expected hop claims, HALT stops only when cumulative evidence supports each required claim. Across three multi-hop QA benchmarks, HALT reduces redundant search while largely preserving exact match. We separate a deployable setting, where hop claims are generated from the question, from a diagnostic upper bound that uses gold supporting-fact annotations: generated claims give smaller but still exact-match-preserving savings, while gold claims show the larger savings available when hop targets are clean. Baseline comparisons and ablations show that this behavior is driven by claim-evidence alignment rather than generic sufficiency, fixed stop positions, or lexical overlap. Open-corpus pilots further suggest that HALT abstains when coverage cannot be reliably verified. Overall, evidence coverage provides a practical runtime control signal for improving retrieval-augmented agents without retraining or modifying the host agent.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题：多跳检索代理的“停止问题”**。在检索增强生成（RAG）系统中，代理化 RAG 会通过多轮迭代检索来回答多跳问题（如 Self-Ask、ReAct、Search-R1 等）。但检索循环存在一个根本性的效率缺陷——**当必要证据已被收集后，继续检索往往是冗余的**，只会额外增加延迟、算力成本，并引入干扰性上下文，反而可能降低最终答案质量。
- **现有方法的不足**。已有的自适应停止方法（如 Self-RAG、Stop-RAG、SIM-RAG、SeaKR 等）普遍依赖**生成器侧或轨迹级的全局信号**（如答案置信度、内部状态不确定性、反思 token 等）来决定是否停止，但这些信号存在本质缺陷：模型可能在证据不充分时也“自信满满”，也可能在证据已完备时继续检索。也就是说，它们没有直接回答一个关键问题：**检索到的证据是否已覆盖问题所需的全部推理跳**。
- **论文的核心主张**：停止问题应当被重新形式化为**证据覆盖（evidence coverage）** 问题，而非生成器置信度问题。即：只有当累计检索到的证据已覆盖问题所需的所有推理跳时，才应停止检索。
- **整体含义**：该工作提供了一种**轻量、模块化、可即插即用**的停止策略——HALT（Hop-Aligned Loop Termination），它不修改宿主搜索代理、不重新训练检索器或生成器，仅仅作为停止条件的“门控信号”，在保持答案准确率的前提下显著削减冗余检索。

## 2. 论文提出的方法论

### 2.1 核心思想
HALT 的关键设计在于：**将“是否停止”从“生成器能否回答”转变为“检索证据是否覆盖了每个预期推理跳”**。其停止谓词是显式的逐跳（per-hop）验证，而非全局轨迹的充分性判断。

### 2.2 技术流程与关键细节
HALT 的完整流水线如下（对应论文图 2）：

1. **预期跳数声明（Expected Hop Claims）构建**——对每个多跳问题 q，构建一组预期推理跳声明 C(q) = (c₁, c₂, …, c_K)，每条声明描述某一推理跳所需的证据。有两种构建来源：
   - **黄金声明（Gold claims）**：由基准数据集的支撑事实（supporting-fact）标注构建，作为诊断性上界（diagnostic upper bound）。
   - **生成声明（Generated claims）**：从问题本身通过 Qwen2.5-3B 零样本生成，是部署时可用的条件。
2. **逐跳验证器 Vθ**——以 Qwen2.5-3B-Instruct 为骨干 + LoRA 适配器进行监督微调，将每条“声明–证据句”对分类为三值标签：**MATCH（匹配）、PARTIAL（部分匹配）、NULL（不匹配）**。推理时采用三标签字符串的长度归一化 token 对数概率取 argmax。
3. **增量运行最大标签更新**——由于证据只增不减，每一轮只对新增句子打分，并按 `MATCH > PARTIAL > NULL` 的优先级维护每个声明的运行标签：
   - ŷ_k⁽ⁱ⁾ = max( ŷ_k⁽ⁱ⁻¹⁾, max_{s∈Sᵢ} Vθ(c_k, s) )
4. **停止策略 π**：
   - **ALL_MATCH（默认）**：当且仅当每个声明均达到 MATCH 时才停止——要求完整的逐跳证据覆盖。
   - **ANY_MATCH（宽松）**：只要任一声明达到 MATCH 就停止——作为对照，验证“匹配一个跳是否足够”。
5. **宿主代理保持不变**：搜索策略、检索器、生成器全部冻结，HALT 只决定“何时停止”，不干预“如何检索”或“如何生成”。

### 2.3 训练数据
- 训练数据自动构建自 HotpotQA：支撑事实提供正例，干扰段落提供反例，通过“差异标签程序”映射到 MATCH/PARTIAL/NULL 三分类。
- 训练集 9,626 行（来自 4,903 个问题），验证集 2,374 行，宏 F1 = 0.9304。
- 验证器只在 HotpotQA 上训练一次，直接被复用到其他数据集和代理规模，无需重新训练。

## 6. 论文的主要结论与发现

1. **HALT 显著减少冗余检索且基本保持 EM**：在 3B 代理 + 黄金声明条件下，检索循环数减少 20%–45%，EM 非劣效性检验在 3 个细胞中通过 2 个（HotpotQA-gold 3B 因 95% CI 穿越 −ε 边界而失败，但点估计仅 −0.9 pp）；生成声明条件下 6 个细胞全部通过 EM 非劣效性。
2. **7B 代理的收益较小但信号一致**：7B 代理天然早停，几乎没有后覆盖搜索可削减（预算耗尽率 0.0–0.5%），因此节省受限是“空间不足”而非信号失效；但所有 7B 黄金声明细胞均通过两项检验。
3. **发现并修复“搜索不足”（under-search）**：7B 代理在 51%–79% 的问题上于未达 ALL_MATCH 覆盖时自行停止。强制续搜至覆盖点后 EM 几乎翻倍（HotpotQA 从 0.162 → 0.323），且优于续搜至满预算，证明覆盖点是比满预算更优的停止目标。
4. **生成声明的部署条件有效但节省较小**：生成声明（无需元数据）产生的节省低于黄金声明，但仍保持 EM；声明与黄金对齐的 F1 为 0.455（HotpotQA）和 0.701（2Wiki），质量越低触发率越低而非虚假触发。
5. **HALT 不是“通用充分性”的变体**：与 V-SIMRAG 的停止循环分歧率 27.7%–66.2%，远超预设的 25% 目标；零样本充分性法官在 HotpotQA 上过早触发（HALT 在此 F1 优于法官 +1.9 pp）。
6. **开放语料下 HALT 表现为“验证感知的选择性预测”**：HotpotQA 上 ALL_MATCH 触发率从设置 A 的 67.6% 降至设置 B 的 6.4%，但触发子集的 EM 为 0.391（人口基线 0.109，提升 3.58 倍）；Bamboogle 上仅 2.4% 触发且零 EM 损失。即：**当覆盖无法可靠验证时，HALT 选择弃权而非冒险停止**。
7. **消融验证核心机制**：随机声明替换使触发率崩溃（0.591→0.034），仅保留页面字段恢复有限（→0.105），词序打乱使触发率崩溃（0.676→0.077）——证明停止信号来自声明-证据对齐，而非页面标题匹配或词袋重叠。

## 7. 优点

1. **问题重构有洞见**：将停止问题从生成器置信度转向证据覆盖，直击多跳检索中“证据是否足够”这一本质问题，概念清洗且可操作。
2. **模块化设计优雅**：不修改宿主代理、不重新训练检索器或生成器，只增加一个轻量验证器作为停止门控，即插即用，对现有系统友好。
3. **逐跳显式验证**：匹配一条相关事实不足以停止，必须所有预期声明都被覆盖，避免了单一强证据误导策略的问题。
4. **双向控制的普适性**：同一覆盖信号既能削减 3B 代理的过度搜索，又能修复 7B 代理的搜索不足，说明其控制的不是“某个代理的行为”而是“停止决策本身”。
5. **统计严谨性**：采用非劣效性检验 + 优效性检验 + 配对 bootstrap + Holm 校正的正式协议，且有 Newcombe CI 和 McNemar 检验的稳健性交叉验证，证据强度高于多数同类工作。
6. **对不利结果坦诚处理**：明确标记 HotpotQA-gold 3B 的 FAIL，不做掩盖；对 7B 小收益给出“空间不足”的机制解释并有 under-search 实验佐证。

## 8. 缺点与局限性

1. **对“循环可观察性”的依赖是部署前提**：HALT 的逐跳验证直接依赖宿主代理暴露出结构化的中间循环状态（如 Self-Ask 的“追问—回答”对）。对于不暴露循环边界或检索轮次的代理（如隐式检索、端到端 Agent 轨迹压缩），HALT 无法直接插入，需要额外改造宿主代理。
2. **开放语料下触发率过低，实用性受限**：在真实开放检索场景（设置 B）中，HALT 在 HotpotQA 上仅对 6.4% 的问题触发停止，在 Bamboogle 上仅 2.4%，几乎退化为默认跑满预算。这虽然避免了错误早停，但也意味着在开放域中 HALT 的节省收益极为有限——问题在于验证器对“证据池已覆盖全部声明”的判定过于严格，生成证据与声明之间的字面差距容易被判为 NULL。
3. **生成声明的质量是水平瓶颈**：部署条件下生成声明与黄金声明的对齐 F1 仅 0.455（HotpotQA），导致触发率显著低于黄金声明条件，节省效果打折。论文虽用更大模型（Qwen2.5-72B）生成声明做了补偿，但没有系统性解决声明生成本身可能遗漏关键推理跳（声明不完整）的问题。
4. **依赖单跳声明拆解的完备性**：HALT 要求每个问题能被拆解为一组完备的预期跳声明。对于路径型、比较型或隐含中间结论的多跳问题，声明拆解可能不唯一；预定义声明集合若与推理路径不同构，则 “ALL_MATCH” 可能永远无法达到（造成过晚停止）或错误提前满足。
5. **效率收益的度量口径存在争议**：论文承认 HALT 在原始 token 数上是净消耗（平均每问题额外 +5k–8.5k token），其效率声明依赖“并行预填充比顺序解码便宜”的工程论断和墙钟时间度量。在批处理吞吐、按 token 计费的 API 服务或长上下文解码昂贵的场景下，该收益可能被显著稀释甚至逆转。
6. **验证器训练域窄**：验证器仅在 HotpotQA 上训练，尽管论文证明了跨数据集迁移有效，但 HotpotQA 的证据句式（维基百科风格事实句）与更广泛领域的检索证据（如法律、医疗、对话记录）存在分布差距，通用性仍需验证。
7. **未与端到端训练式停止方法在同一框架内比较**：论文的基线主要是基于分类器或启发式的即插即用方法，未与现代端到端强化学习式代理（如 Search-R1 系列、带奖励模型的停止智能体）进行直接比较；这使“HALT 是否优于训练式停止策略”这一问题悬而未决。
8. **停止点未必是最终答案的最优点**：HALT 将停止目标定为“证据覆盖”，但从 7B 代理的 under-search 实验来看，达到全部覆盖后 EM 仍只有 0.162–0.323，远非高精度；即证据覆盖是停止的必要条件而非充分条件，两者之间存在差距，论文未就“覆盖后如何进一步收敛答案质量”给出方案。

## 9. 总体评价与学术定位

**定位**：HALT 属于“轻量外部监控层”路线的代表性工作，与训练式自适应检索（如 FLARE 系）和生成器置信度式停止（如 Self-RAG 系）形成互补关系，而非替代关系。它的独特贡献在于首次将停止问题精确刻画为**逐跳证据覆盖的谓词验证**，使“何时停止”从模型内部状态的黑盒判断转化为可解释、可审计、可单元测试的证据覆盖判定。

**价值判断**：该工作的学术贡献主要在三个方面——（1）**概念层面的重新定义**：停止 ≠ “模型是否自信”而是“证据是否完整”；（2）**方法论层面的可移植架构**：验证器与宿主代理解耦，任何暴露循环的检索代理都能挂载；（3）**实证层面的双向控制发现**：同一信号既能抑制过度搜索又能修复搜索不足，这一发现对检索代理的预算分配机制具有普遍启发。其弱项在于开放域实用性、Token 级成本口径和端到端训练式方法的缺失比较。

**一句话概括**：HALT 通过一个轻量的逐跳声明验证器，将多跳检索代理的停止决策从“模型感觉够了”重构为“证据证明够了”，在保持答案质量的同时显著削减冗余检索，并为开放域下的验证不可靠问题提供了一条“宁可少停、不可错停”的保守策略。
