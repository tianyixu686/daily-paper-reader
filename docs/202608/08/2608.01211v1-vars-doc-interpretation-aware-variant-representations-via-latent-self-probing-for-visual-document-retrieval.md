## 摘要
视觉文档检索最近在企业搜索、科学文献发现和检索增强生成等应用中变得越来越重要。这些应用依赖于在大量视觉丰富的文档集合中高效识别与查询相关的页面。现有方法通常采用后期交互架构，离线编码和索引文档，以实现可扩展和低延迟的在线检索。尽管高效，但该范式要求每个文档在查询已知之前被编码为固定表示。然而，视觉文档中的相同内容可能会根据查询意图产生不同的解释，而固定表示难以捕捉这一点。但是，将文档编码推迟到查询到来时又会带来高昂的在线检索延迟。为了解决这一差距，我们提出了 VaRS-Doc，一种视觉文档检索框架，通过使模型在文档编码期间主动探索变体潜在解释来多样化文档表示，同时保留高效的后期交互检索，其中每个查询自适应地选择最合适的表示。我们进一步引入了一种两阶段训练策略，鼓励模型捕捉互补的语义解释，并防止其退回到训练单一主导表示。在视觉文档检索基准上的实验表明，VaRS-Doc 实现了最先进的检索性能，为查询无关的文档编码与查询特定的检索需求之间的不匹配提供了一种实用解决方案。代码可在 https://github.com/bokufa/VaRS-Doc 获取。

## Abstract
Visual document retrieval has recently become increasingly important in applications such as enterprise search, scientific literature discovery, and retrieval-augmented generation. These applications depend on efficiently identifying query-relevant pages across large collections of visually rich documents. Existing methods commonly adopt late-interaction architectures that encode and index documents offline to enable scalable and low-latency online retrieval. Despite its efficiency, this paradigm requires each document to be encoded into a fixed representation before the query is known. However, the same content in a visual document may induce different interpretations depending on the query intent, which a fixed representation struggles to capture. Yet postponing document encoding until the query arrives would incur prohibitive online retrieval latency. To address this gap, we propose VaRS-Doc, a visual document retrieval framework that diversifies document representations by enabling the model to actively explore variant latent interpretations during document encoding, while preserving efficient late-interaction retrieval in which each query adaptively selects the best-fit representation. We further introduce a two-stage training strategy that encourages the model to capture complementary semantic interpretations and prevents it from falling back to train a single dominant representation. Experiments on visual document retrieval benchmarks show that VaRS-Doc achieves state-of-the-art retrieval performance, offering a practical solution to the mismatch between query-agnostic document encoding and query-specific retrieval needs. Code is available at https://github.com/bokufa/VaRS-Doc.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心矛盾**：视觉文档检索（Visual Document Retrieval）在大规模场景中常采用**晚期交互（Late-Interaction）架构**，即文档需在查询到达前**离线编码为固定表示**以保证检索效率。然而，同一视觉文档内容（如一个图表）可能因查询意图不同而需要不同的语义解读（例如“比较各区域贡献”vs“评估亚洲市场潜力”）。固定表示无法适配这种查询特定的多义性。
- **现有方案的不足**：
  - **晚期交互方法（如ColPali）**：高效但文档表示固化，只能提供一种“通用”解读，限制了查询匹配的准确性。
  - **交叉编码方法（如Qwen3-Reranker）**：可针对查询动态解读文档，但需要在查询时对全部文档重复编码，无法复用离线索引，在线延迟极高，不适于大规模召回。
- **核心科学问题**：如何在**保持离线索引可扩展性**的同时，让文档表示具备**查询自适应的多义性解读能力**？论文将这一问题形式化为“查询无关编码”与“查询特定检索需求”之间的失配（Gap）。
- **解决思路**：在离线编码阶段，通过**潜在自探测（Latent Self-Probing）** 机制主动为每篇文档生成**多个互补的变体表示（Variant Representations）**，使模型在未见查询时即可“预判”多种可能的解读方向。在线检索时，查询仅需编码一次，并从预计算的多个变体中**选择最匹配的一个**，兼顾了效率与解读灵活性。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心框架：VaRS-Doc
该框架由三个关键组件构成，核心思想是将文档编码过程分为“共享上下文读取”与“探针引导的分支编码”两阶段。

### (1) 潜在解释探测令牌（Latent Interpretation Probing Tokens）
- **实现方式**：在文档编码器中插入 **K 个可学习的潜在探针令牌（Probing Tokens）**，拼接在文档令牌之后。
- **作用机制**：这些令牌**首先静默读取文档上下文**（不反向影响文档令牌编码），成为文档条件化的探针；随后，每个探针引导不同的编码分支，使各分支对同一文档产生不同的语义侧重点。
- **优势**：相比依赖人工定义的自然语言提示，潜在探针通过检索监督自动发现互补且任务相关的解读方向，避免了对提示词措辞的敏感性。

### (2) 共享上下文化与分支编码（Shared Contextualization with Branched Encoding）
该设计将文档 LLM 编码器分为两阶段，以实现高效的多解释生成。

- **阶段一：共享语义上下文化（L - n 层）**
  - 所有文档令牌和探针令牌按照 `U = [文档令牌; 探针令牌]` 的顺序拼接输入。
  - 利用 LLM 原有的**因果注意力掩码**，保证文档令牌不能看到探针令牌，而每个探针令牌可以关注所有文档令牌（公式4）。
  - 输出共享的文档状态和文档条件化的探针状态。

- **阶段二：探针引导的分支编码（最后 n 层）**
  - 将共享隐藏序列**复制为 K 个分支流**（公式6）。
  - 为每个分支设置一个**特定的二进制可见性掩码** `A(k)_br`，该掩码在原有因果掩码基础上，**额外允许所有文档令牌关注分支 k 对应的探针令牌**（公式7）。
  - 每个分支使用自己的掩码，在最后的 n 层 Transformer 中独立编码。这样，每个分支中的文档令牌都能获得不同的解读上下文，从而生成不同的文档变体表示（公式8-10）。
  - 探针令牌**不参与最终的查询匹配**，它们仅作为指导信号，通过影响注意力机制来影响最终表示。

### (3) 变体感知的晚期交互（Variant-Aware Late Interaction）
- **索引阶段**：每篇文档 `d` 被表示为 K 个变体嵌入的集合（公式11）。
- **检索阶段**：查询 `q` 独立编码（公式12），对每个变体计算经典的 **MaxSim 分数**（公式13），最终的文档相关性得分取 **K 个变体分数的最大值**（公式14）。这使每个查询能自适应地激活该文档下最匹配的解读表示。

### 2.2 两阶段训练策略（Two-Stage Variant Optimization）
为了防止多分支模型从随机初始化训练时出现**分支坍缩（Branch Collapse）** 问题（即一个分支主导几乎所有查询，其余分支训练不充分），论文设计了如下训练流程：

- **第一阶段：单变体预热（Single-Variant Warmup）**
  - 先训练一个非分支的标准检索器（K=1），学习稳定的查询-文档嵌入空间。
  - 训练损失采用**排序损失**（公式15）。
  - 训练收敛后，将其**复制**到 K 个分支实例，确保每个分支以“强竞争者”身份进入下一阶段。

- **第二阶段：多变体适应（Multi-Variant Adaptation）**
  - 采用组合目标函数（公式21）打破复制带来的对称性，促使分支专业化：
    - **硬负样本感知检索损失（Hardness-Aware Retrieval Loss）**：改进版 InfoNCE 损失（公式16），根据负样本的当前相似度分数动态增加其权重（公式17），使模型聚焦于难分辨的查询-文档对。
    - **批次级平衡损失（Batch-Level Balance Loss）**：鼓励在一个批次内各变体的使用率接近均匀分布（公式18、19），防止单个变体长期垄断；防止全局坍缩。
    - **批次级多样性损失（Batch-Level Diversity Loss）**：通过最大化最优变体分数与次优变体分数之间的差值（公式20），促使每个查询能清晰地区分出最佳解读变体，避免模糊性；防止样本内坍缩（各变体分数几乎相同）。

- **对比方法**：
  - **视觉-语言对比模型**：CLIP、SigLIP。

- **主要结果**：VaRS-Doc 在 ViDoRe V2 和 V3 上均达到**最先进的平均性能**（66.5 和 56.7），总体平均 60.0。相比直接基线 ColQwen2.5，在**全部 12 个数据集上均有一致性提升**，总体平均提升 4.5 个百分点，尤其在经济报告（+7.1）、工业文档（+7.7）和ESG报告（+7.0）上增益显著。

## 6. 论文的主要结论与发现

- **核心结论**：论文验证了“**为文档准备多个解释，优于将其压缩为一个固定表示**”这一核心假设。通过让模型主动探索潜在解读空间，可以弥合查询无关编码与查询特定检索需求之间的鸿沟。
- **技术发现**：
  - **分支编码，而非简单的探针或投影头，是实现解释多样化的关键**（仅分支编码即可将性能从 62.1 提升至 65.8）。
  - **两阶段训练是防止多分支模型陷入单分支主导的关键**。缺少单变体预热会使最大分支使用率飙升至 94.2%；缺少平衡损失同样会导致全局分支坍缩（92.4%）；缺少多样性损失会导致变体间区分度极低（Tie Rate 从18.9%升至56.8%）。
  - 变体表示在语义上具备**稳定性与特异性**：相同意图的改写查询有77.6%的概率选择同一变体，而不同意图的查询仅有30.8%概率选择同一变体，证明不同变体确实捕捉了互补的语义解读。

## 7. 优点（方法或实验设计上的亮点）

- **创新性的问题建模**：精准地识别了晚期交互架构中一个隐蔽但重要的缺陷，并提出了优雅的解决方案。将“查询特定的解读”转化为“离线准备好变体，在线自适应选择”，巧妙地在效果、成本和延迟之间取得了平衡。
- **方法设计的精巧性**：
  - **潜在自探测** 通过可学习令牌，避免了人工定义解释空间的成本与局限。
  - **共享上下文化与分支编码** 只需对最后的 n 层进行分支重复计算，K=5时索引时间仅增加14%，非常高效。
  - **两阶段训练策略**具有高度针对性，清晰地区分并解决了多变体训练中“全局坍缩”和“样本内模糊”两种不同的问题，体现了对模型分化的深层思考。
- **实验验证的严谨性**：除了性能对比，还通过精心设计的“解释互补性分析”（控制意图的生成查询对与人工校验）和效率分析，多维验证了方法的有效性与实用性。
- **实用性**：在A800 GPU上查询延迟仅增加约5ms（27.15ms vs 22.38ms），对于生产部署而言是极佳的性价比，且开源代码有助于进一步研究。

- **实验泛化性有待进一步验证**：所有主实验均基于单一骨干模型（ColQwen2.5）和单一训练数据源（ColPali训练集）。将该方法应用于其他MLLM骨干（如PaliGemma、Qwen3-VL）、更丰富的训练数据（如结合指令微调或检索微调数据）或其他语言的文档（如ViDoRe V3中的多语言任务）时，其增益是否依然显著还有待验证。
- **变体的可解释性局限**：虽然变体被证明在语义上有区分度，但论文来并未深入展示每个变体究竟对应何种具体语义主题或解读方向，其表征的语义维度仍是隐性的、难以直接人为解读的。
- **未涉及与大规模重排器联合部署的性能评估**：论文聚焦于召回（Recall）阶段，实际RAG系统中通常包含重排（Rerank）步骤，论文未评估在引入重排器后整体检索链路最终的端到端效果与收益。
