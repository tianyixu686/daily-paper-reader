## 摘要
用户与LLM智能体之间的交互正日益多模态化：对话将文本与图像交织在一起，后续的问题可能针对其中任何一种。然而，大多数智能体记忆都是围绕文本设计的，即便是少数支持多模态对话的系统，在面对与视觉相关的问题时仍然会失败。我们将这种失败归因于其依赖的相似性搜索背后的一个假设：在索引空间中，查询与其回答所需的相关证据距离很近。在多模态设置中，有两个间隙打破了这一假设。由于模态间隙，查询在训练过的联合嵌入空间中，与其自身模态的记忆内容距离更近，而非另一模态的证据。由于相似性-相关性间隙，与查询最相似的内容往往不是回答该查询的证据，当查询同时包含文本和图像，且其证据与任何单独部分都不相似时，这种情况最为严重。我们提出了V-Mem，一种多模态智能体记忆系统，它通过查询的模态和目标证据的模态（两者都仅从查询中识别）来路由检索。为了跨越模态间隙，V-Mem将对话组织为轮次，并从匹配所在的轮次返回目标模态的内容，而不进行跨模态比较。为了弥合相似性-相关性间隙，它使用LLM生成的锚点进行搜索，该锚点比查询更接近相关证据：对于仅请求图像的纯文本查询，使用一个假设性标题；当证据只能通过结合文本和图像才能获得时，则使用一个增强搜索锚点，即查询文本加上从查询图像中提取的相关关键词。在Mem-Gallery上，V-Mem的LLM评判得分为0.82，而第二名的得分为0.56，在携带图像的问题上优势最大（0.87，而基线均不超过0.47）；在LoCoMo上，其得分为0.69，而后者为0.58。

## Abstract
Interaction between users and LLM agents is increasingly multimodal: conversations interleave text with images, and a later question may target either. Yet most agent memories are designed around text, and even the few that support multimodal conversations still fail on vision-related questions. We trace this failure to an assumption behind the similarity search they rely on: in the index space, a query lies close to the relevant evidence that answers it. In multimodal settings, two gaps break it. By the modality gap, a query lies closer to memory content of its own modality than to evidence in another, even in a trained joint embedding space. By the similarity-relevance gap, the content most similar to a query is often not the evidence that answers it, most acutely when a query carries both text and image and its evidence resembles neither part alone. We present V-Mem, a multimodal agentic memory system that routes retrieval by the modality of the query and that of the target evidence, both recognized from the query alone. To cross the modality gap, V-Mem organizes the conversation into rounds and returns the target-modality content from the same round as the match, without comparing across modalities. To close the similarity-relevance gap, it searches with an LLM-generated anchor that sits closer to the relevant evidence than the query does: a hypothetical caption for a text-only query seeking an image, and an enriched search anchor, the query text plus relevant keywords extracted from the query image, when the evidence is reachable only by combining the two. On Mem-Gallery, V-Mem reaches an LLM-judge score of 0.82 versus 0.56 for the second best, with the largest margin on questions carrying an image (0.87, no baseline above 0.47); on LoCoMo it scores 0.69 versus 0.58.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：LLM 智能体作为长期运行的助手，会积累数周甚至数月的多模态对话历史（文本、图片、语音交错）。然而，LLM 本身只处理当前上下文窗口，早期信息一旦被挤出便不可用。Memory-Augmented Generation（MAG）将交互历史存储于外部，并在每次新轮次中检索相关片段。但现有 MAG 系统大多只支持文本，少数支持多模态的系统在视觉相关问题上仍然失败。
- **核心问题**：V-Mem 论文将该失败追溯到相似性搜索背后的一个隐含假设——"在索引空间中，查询与其相关证据距离很近"。在多模态场景下，这个假设被两个"间隙"打破：
  - **模态间隙（Modality Gap）**：当查询与证据属于不同模态时，即使使用 CLIP/SigLIP 这类联合嵌入空间，查询仍更接近同模态的记忆内容，而非跨模态证据。
  - **相似性-相关性间隙（Similarity-Relevance Gap）**：与查询最相似的内容往往并非回答它所需的证据，最极端的场景是查询同时携带文本和图像，其相关证据与二者单独都不相似，必须将两者结合才能定位。
- **整体含义**：V-Mem 提出了一种新的检索范式：不依赖跨模态嵌入对齐，而是**按模态路由检索**，通过对话结构（轮次）和 LLM 生成的搜索锚点分别弥合上述两个间隙。在 Mem-Gallery 上达到 LLM-judge 得分 0.82（第二 名 0.56），带图像问题上达 0.87（无基线超过 0.47）；在 LoCoMo 上 0.69 vs 0.58。

## 2. 论文提出的方法论

### 2.1 核心思想
V-Mem 将交互历史组织为**轮次（rounds）**，每个轮次是一次用户-助手交换，包含若干**记忆单元（units）**（单个文本片段或单张图像）。所有单元按模态存入两条**通道（lane）**：文本通道（含图像标题文本）和图像通道（原始图像的视觉嵌入）。检索时，**路由（routing）** 仅从查询本身（无需 LLM 调用）推断（查询模态，目标模态）配对，只激活所需通道，并按配对选择搜索锚点和返回策略。

### 2.2 四种检索情形
| 情形 | 处理方式 |
|---|---|
| 文本→文本 | 文本通道直接检索，用原始查询 |
| 图像+文本→图像 | 图像通道用查询图像做视觉相似度匹配 |
| 文本→图像 | 文本通道（限定在含图像的轮次内）匹配，返回轮次中的图像；用 LLM 生成**假设标题（hypo-caption）** 作为锚点；计数类问题跳过假设标题 |
| 图像+文本→文本 | 视觉 LLM 从查询图像提取关键词，拼接查询文本形成**富化搜索锚（enriched anchor）**；图像通道同时匹配查询图像 |

### 2.3 两类关键机制
- **通过共享轮次匹配（Matching through shared rounds）**：跨模态情形下，查询只在自身模态通道内匹配，找到 top 匹配的轮次后，返回该轮次中目标模态的内容。轮次内单元共现，通常相互关联，因此无需跨模态比较即可抵达另一模态的证据。
- **LLM 生成的锚点（Searching with a generated anchor）**：
  - 文本→图像：LLM 将查询改写为"目标图像可能有的标题"，与存储图像的标题匹配；
  - 图像+文本→文本：视觉 LLM 从查询图像中提取回答轮次可能包含的关键词（最多 8 个），拼接到查询文本后作为锚点。

### 2.4 评分与融合公式
每个激活通道的信号（稠密嵌入余弦、BM25、视觉嵌入余弦）计算单元级分数：

\[
s_j(u) = \cos(e_j(a_{c,\ell}), e_j(u)) \quad \text{或 BM25}
\]

轮次得分为其单元的最高分；不同信号按**倒数排名融合（RRF）** 合并，避免尺度差异：

\[
\text{score}(r) = \sum_{j \in J_c} \frac{1}{\kappa + \text{rank}_j(r)}
\]

（κ=60）。返回 top-k 轮次时，每个轮次附带 ±1 相邻轮次（聚合计数类问题去掉邻居、扩大 k）。检索流程如 Algorithm 1：路由确定可搜索单元集合 U、锚点集合 A，其后各通道统一评分、融合、取轮次、组装上下文。

### 2.5 记忆构建
零 LLM 抽取：保留每个文本片段和图像，语音转写为文本单元，图像标题也折入文本索引。增量式构建，每轮就地编码，无需重写历史。

## 6. 论文的主要结论与发现

- V-Mem 在两个 Benchmarks 上均显著超越多模态与文本记忆基线：Mem-Gallery 0.825 vs Omni 0.561；LoCoMo 0.690 vs 0.583；在更强骨干（Qwen2.5-VL-32B）下 0.829 vs 0.628。
- 最大优势集中在**带图像的问题（TTL 0.872 vs 次优 0.472）** 与视觉推理（VR 0.575 vs 次优 0.273）；在 CD、KR、MR 等非视觉类别上同样领先，说明优势不仅来自视觉处理。
- 消融显示：**通过共享轮次匹配是最大单一贡献（总体 +0.129）**，直接补上了 routing 在视觉类别上的损失；生成锚点在触发类别（VR +0.038, VS +0.032）有效。
- 记忆构建零 token、数秒完成，是构建成本上最干净的胜利（vs 基线数百万 token、数小时以上）。
- 关键约束：V-Mem 对骨干容量敏感，在 Qwen2.5-VL-7B 下被 Omni 反超（0.509 vs 0.534）；附加图像描述的措辞会导致回答模型被误导（如"Blue Mosque" vs "Hagia Sophia"）。

## 7. 优点

- **问题诊断深刻**：清晰地将多模态记忆检索失败归因于两个可操作的"间隙"，并有针对性的机制一一对应。
- **设计简洁、无需训练**：全部使用现成编码器与 LLM，零微调，构建零 token 成本；路由与目标模态判断通过关键词规则实现，不产生额外 LLM 调用。
- **模块化与可解释**：每种机制对应一种失败模式，消融实验逐层验证，因果链条清晰。
- **方法新颖**：用"轮次"作为跨模态中介（替代学习联合嵌入）、用"假设标题/富化锚点"弥合相似性-相关性差距，思路务实：避免直接跨模态比较，绕开模态间隙。
- **实验严谨**：共享骨干/编码器/Judge、原实现基线、配对显著性检验、多种消融与补充分析（成本、邻居放置、图像编码器、错误分析）一应俱全，并对消融中不显著的步骤坦诚说明。

## 8. 不足与局限

- **骨干依赖性强**：返回轮次+邻居的上下文由回答模型自行提取答案；较弱骨干（7B）会因额外上下文干扰而失效，甚至落后于 Omni。论文将此列为局限性。
- **仅覆盖图像+文本**：音频按文本转写处理，两个基准均不含音频/视频，第一类多模态记忆（音视频自己的检索通道）未测试。
- **生成锚点的代价**：视觉问题每问触发一次视觉 LLM 调用（最多 8 关键词），增加 token 与延迟；富化锚点在全部 468 问上仅 +0.004（40 改进 / 35 恶化），靠设计动机而非总体收益支撑。
- **LoCoMo 无真实图像**：该基准只提供图像标题文本，视觉检索能力未在该基准得到验证。
- **词法指标不统一**：Mem-Gallery 上 V-Mem 全面领先，但 LoCoMo 上词法指标偏向 Omni（因其长答案风格），需依赖 LLM-judge 作为主指标。
