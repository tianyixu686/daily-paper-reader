## 摘要
中期训练（mid-training）日益被认为是塑造大型语言模型能力的关键阶段。近期研究表明，有针对性的中期训练能够增强数学、科学等推理密集型能力，也能提升软件工程场景中的智能体能力。在本工作中，我们研究了一个并行但探索较少的智能体能力：通用工具使用。我们提出了MidTool，一个面向智能体工具使用中期训练的开源语料构建流水线，它结合了大规模网页、PDF和代码数据，以及来自真实世界工具API、MCP技能和基于文档的工作流的合成监督信号。MidTool旨在教导模型识别工具可供性、从上下文中确定参数依据、组合工具调用工作流，并从信息不完整中恢复。我们在MidTool-Mix上对Qwen3-4B-Base和Qwen3-8B-Base进行中期训练，然后应用监督微调和强化学习进行后续后训练。与基线相比，MidTool-Mix在BFCL、tau2-Bench和MCP Universe上的一致地提升了SFT和RL下的下游性能。这些结果表明，通用工具使用与其他重要的LLM能力一样，受益于专门的中期训练，而非完全留给后训练。

## Abstract
Mid-training is increasingly recognized as a critical stage for shaping the capabilities of large language models. Recent work has shown that targeted mid-training can strengthen reasoning-intensive abilities such as math and science, and can also improve agentic capabilities in software-engineering settings. In this work, we study the parallel but less explored agentic capability: general tool use. We present MidTool, an open corpus construction pipeline for agentic tool-use mid-training that combines large-scale web, PDF, and code data with synthesized supervision from real-world tool APIs, MCP skills, and document-grounded workflows. MidTool is designed to teach models how to recognize tool affordances, ground arguments from context, compose tool call workflow, and recover from incomplete information. We mid-train Qwen3-4B-Base and Qwen3-8B-Base on MidTool-Mix, and then apply follow-up post-training with both supervised fine-tuning and reinforcement learning. Compared with baselines, MidTool-Mix consistently improves downstream performance under both SFT and RL on BFCL, tau2-Bench, and MCP Universe. These results suggest that general tool use, like other important LLM capabilities, benefits from dedicated mid-training rather than being left entirely to post-training.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：工具使用已成为 LLM 智能体的核心能力之一，包括判断何时调用外部工具、根据工具 schema 构造参数、从长且嘈杂的上下文中提取参数、组合多工具工作流、以及信息不完整时的恢复能力。此前大部分进步来自后训练（SFT/RL）。
- **问题**：现有中期训练（mid-training）研究主要聚焦数学推理、深度研究、代码和软件工程（SWE）等领域，通用工具使用作为中期训练目标仍被忽视。工具使用所需知识分散在文档、PDF、代码、API 规范等非轨迹数据中，后训练数据难以全面覆盖，因此作者提出：通用工具使用是否也应享有专门的中期训练阶段？
- **核心主张**：通用工具使用不应完全留给后训练，而应通过专门的中期训练注入更广泛的工具使用先验（tool-use prior），从而为后续 SFT/RL 提供更强的底座。

## 2. 论文提出的方法论

- **总体框架**：作者提出 MidTool，一个可扩展的开放式语料构建流水线，最终生成 **MidTool-Mix**（20.3B tokens，11.22M 样本）。流程分为三个阶段：
  1. **数据源收集**：四大互补来源
     - Web 数据：FineWeb 多个 dump（2020–2025），提供 API 文档、教程、CLI 指南等技术内容。
     - PDF 数据：FinePDFs 英文子集，提供长篇幅程序性手册、产品文档。
     - 代码数据：基于 GitHub Archive，过滤得到两个切片（agent/MCP 相关仓库和高星优质仓库），排除 benchmark 仓库。
     - 工具数据：真实 REST API 与 MCP skills，为轨迹合成提供显式 schema。
  2. **数据预处理**：针对不同源设计专用过滤管线，包括关键词/URL 预筛选、fastText 分类器、质量过滤、MinHash LSH 去重；代码则采用 StarCoder 风格启发式过滤和文档目录匹配。
  3. **智能体轨迹合成**：两条互补分支
     - **Context-grounded Trajectory Augmentation**：从网页/PDF/代码文档中提取 affordance 画像，使用 Qwen3-235B 教师模型生成 QA 对和多轮轨迹，强化“从文档中接地工具调用”的能力，覆盖工具选择、参数提取、格式约束、工作流识别等原子能力。
     - **Native Agentic Trajectory Synthesis**：从真实 API 组和 MCP skills 构建工具清单，用 GPT-5 系列模型分配质量分数和可行性画像，并通过 planner 生成多样 personas 的多轮轨迹，严格验证 turn 顺序、schema 接地、必需参数和工具响应一致性；同时混入 AWM（Agent World Model）的 rollout 轨迹及过滤后的 Nemotron Agentic 数据。
- **最终语料构成**：Web 42%、Code 26%、PDF 23%、原生 agentic 轨迹 9%；将轨迹统一为普通 chat 格式，不引入特殊控制 token。

## 3. 实验设计

- **基础模型与训练配方**：选择 Qwen3-4B-Base 和 Qwen3-8B-Base，在 MidTool-Mix 上中期训练，随后统一进行 SFT（TOUCAN 100K 子集）和可选的基于 GRPO 的 RL（AWM 提供 526 个合成工具环境）。基线包括：
  - 原始 base + SFT / SFT+RL；
  - 官方 Qwen3 后训练模型（作为参考）；
  - 匹配预算的通用中期训练语料 Dolmino-20BT。
- **Benchmark**：
  - **BFCLv3**：函数调用质量，覆盖单轮/多轮，多轮含 Missing Function、Missing Parameters、Long Context 和 Hallucination 子项。
  - **τ2-Bench**：交互式任务完成（航空、零售、电信等垂直场景），报告 Pass@1/Pass@4。
  - **MCP-Universe**：真实 MCP 服务器上的工具泛化，覆盖浏览器自动化、金融、地理位置、多服务器、Web 搜索等域。
- **消融实验**：固定 4B + SFT 设置，变化中期训练语料——无中期训练、Dolmino-20BT、仅处理后 raw 数据、raw + native 轨迹、raw + context-grounded 轨迹、完整 MidTool-Mix。
- **附加实验**：
  - SFT 损失收敛曲线分析（对比 base vs. Dolmino vs. MidTool-Mix 初始化）；
  - RL 奖励曲线分析（4B/8B）；
  - 视觉工具使用 pilot：在 gemma-3-4b-pt 上中期训练，再在 FineVision 子集 + 文本工具 SFT 上微调，用 VisualToolBench 单轮子集评估。
- **污染审计**：在数据收集阶段排除 benchmark 仓库，并用 DeCon 对最终语料检测，未发现真实泄漏。

## 4. 资源与算力

## 6. 主要结论与发现

- **中期训练显著提升下游工具使用能力**：在 BFCL、τ2-Bench、MCP-Universe 上，MidTool-Mix 在 4B/8B 上均优于纯 SFT 基线，且 RL 通常能进一步放大增益，尤其在多轮、长交互和陌生人工具场景。
- **两分支互补**：Native agentic 轨迹对精确函数调用（BFCL）增益最大；Context-grounded 增强对交互式和迁移性任务（τ2-Bench、MCP-Universe）更重要；只有组合两者才能在全部 8 项指标上相对无中期训练取得提升。
- **迁移性强**：对未见过的 MCP 工具、真实交互环境（如航空、零售）展现出可迁移的先验。
- **发现能力边界**：MCP-Universe 的 Web Search 子集在所有设置下均为 0 分，而其他域（浏览器、金融、位置）有显著提升，说明通用工具使用先验不足以支撑深度搜索类探索行为，这类能力需要专门的轨迹数据和训练目标。
- **优化视角**：MidTool-Mix 提供更好的初始化，使 SFT 损失更低、RL 早期奖励上升更快，但最终泛化差距仍体现在 benchmark 而非训练环境奖励上。

## 7. 优点

- **选题新颖且定位明确**：首次将“通用工具使用”作为中期训练目标，区别于数学、SWE 等已有方向。
- **数据来源多样**：Web、PDF、代码、真实 API/MCP 四源融合，兼顾广度和结构。
- **两分支合成设计合理**：分别针对“接地”（grounding）和“执行”（execution）两类缺陷，可解释性强且消融验证了互补性。
- **工程严谨**：收集阶段排除 benchmark 仓库、后验 DeCon 审计、轨迹验证与重试机制，尽量控制数据泄漏和合成噪声。
- **开源开放**：提供数据与模型，便于复现（Data & Model: hf.co/collections/MidTool）。
- **额外探索**：视觉工具使用的小规模 pilot 展示了跨模态迁移线索，为后续研究提供方向。

## 8. 不足与局限

- **能力边界未解决**：Web Search 子集始终为 0，说明当前通用工具使用中期训练不能覆盖深度搜索/探索型 agent 行为，需要专门数据。
- **强教师依赖**：两类合成轨迹均依赖专有或超大规模教师模型（GPT-5 系列、Qwen3-235B），虽然消融显示 raw data 已有效果，但完整语料仍受教师质量制约。
- **下游协同未探索**：作者刻意固定下游配方，因此中期训练与 SFT/RL 的交互关系（如 SFT 数据规模、RL 环境选择）尚未研究。
- **消融范围有限**：仅 4B + SFT 下做了语料消融，未覆盖 8B、RL 场景；也未做严格同预算的全组合对比。
- **污染检测局限**：DeCon 仅基于表面 n-gram 重合，无法排除语义或 schema 级别泄漏风险。
- **视觉 pilot 证据较弱**：仅单轮子集、评估实现自建，且与主文文本工具设置的关联有限。
- **部分子任务仍困难**：如 τ2-Bench 的 telecom 域、MCP 的某些泛化域提升不明显，说明通用工具使用之外还需领域专门化。
