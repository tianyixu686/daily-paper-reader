## 摘要
在具身场景中准确且高效地回答问答题面临显著挑战，因为视觉语言模型（VLM）推理的计算和内存资源有限。现有方法采用视觉搜索关键帧检索方法，为VLM输入选择与问题相关的关键帧。然而，视觉搜索方法效率低下，因为每个用户查询都需要在数千个视频帧中进行视觉搜索。在这项工作中，我们提出了一种记忆树引导的关键帧选择范式，用于具身场景中的高效三维问答。我们的方法利用一种紧凑且可复用的三维场景表示，称为MemTree3D，它支持利用相机6自由度姿态进行实时在线构建。MemTree3D捕获多级三维场景信息，使大型语言模型能够通过基于评分的帧选择高效查询和检索与问题相关的关键帧，而无需重新处理整个视频流。在OpenEQA上，我们的方法将GPT-4o的LLM-Match提高了17.4%，LLaVA-OneVision-7B提高了5.8%，优于现有视觉搜索方法。我们的代码可在https://github.com/hsiangwei0903/MemTree3D获取。

## Abstract
Answering questions accurately and efficiently in embodied scenarios presents significant challenges due to limited computational and memory resources for Vision Language Model (VLM) inference. Existing methods adopt visual search key frame retrieval method to select critical question-related key frames for VLM input. However, visual search methods are inefficient because they require visual search among thousands of video frames for each individual user query. In this work, we propose a memory tree guided key frame selection paradigm for efficient 3D question answering in embodied scenarios. Our method leverages a compact and reusable 3D scene representation, termed MemTree3D, which supports real-time online construction leveraging camera 6-DoF poses. MemTree3D captures multi-level 3D scene information, enabling a Large Language Model to efficiently query and retrieve question-relevant key frames through our scoring-based frame selection without reprocessing the entire video stream. On OpenEQA, our method improves the LLM-Match of GPT-4o by 17.4%, LLaVA-OneVision-7B by 5.8%, outperforms existing visual search methods. Our code is available at https://github.com/hsiangwei0903/MemTree3D

- **问题定义**：在具身智能场景中（如室内机器人和增强现实），3D 问答要求系统基于视觉语言模型（VLM）对三维场景视频进行理解和推理，但 VLM 的 Transformer 注意力机制计算与内存开销随输入视频帧数呈二次增长，而具身设备上计算和 GPU 内存资源有限。
- **现有方法的缺陷**：
  - **多帧 VLM 方法**：虽可直接处理 3D 扫描视频，但需时间降采样，导致视觉信息丢失，计算成本随视频长度线性增长；
  - **场景图方法**（如 ConceptGraphs）：使用对象级场景图 + LLM 问答，表示粗糙、丢失细粒度视觉信息，且构建流程依赖多个基础模型、通常无法实时；
  - **视觉搜索方法**（如 VLM-Grounder）：通过物体检测器对每个查询在全部视频帧中搜索目标对象，存在三大局限：① 查询延迟随视频长度线性增长，难以实时交互；② 每个查询都必须重新执行视觉搜索，无法高效处理多轮问答；③ 当检测器漏检目标对象时，缺乏失败恢复机制。
- **核心目标**：设计一种高效、鲁棒、可复用的关键帧选择范式，在不牺牲准确率的前提下大幅降低 3D 问答推理的计算开销。

## 2. 方法论

### 2.1 核心思想
提出 **MemTree3D 引导的关键帧选择范式**：先在线构建一个紧凑、可复用的多级 3D 场景表示 MemTree3D；用户查询到达后，由 LLM 对 MemTree3D 进行推理，生成**时间线索**和**空间线索**，据此高效检索与问题相关的关键帧，再由 VLM 基于这些关键帧给出最终答案。整个流程完全避开对视频流的逐帧视觉搜索。

### 2.2 MemTree3D 场景表示（三级树结构）
| 节点层级 | 功能与内容 |
|---|---|
| **Location Node（位置节点）** | 利用相机 6-DoF 位姿将视频流切分为多个空间段（每个段代表场景中的一个位置），每个节点含唯一位置 ID。切分规则：相邻帧间平移超过阈值 T_thres（1.5m）或旋转超过 R_thres（45°）时即新建位置节点。 |
| **Object Node（对象节点）** | 由 YOLO-World 目标检测器 + BoT-SORT 多目标跟踪器获得物体时间轨迹，每个位置节点包含多个对象轨迹节点，记录对象类别与跟踪 ID。 |
| **Detection Node（检测节点）** | 叶节点，记录每帧的检测结果：时间戳、边界框坐标、检测置信度，用于后续评分选帧。 |

### 2.3 LLM 时空线索生成
- 将 MemTree3D 的 LocNode 和 ObjNode（不含 DetNode）序列化为 JSON 文本输入 LLM；
- LLM 输出两类线索：
  - **时间线索（Temporal Cues）**：预测最可能包含答案的 top-k 个位置节点（本文默认 k=3）；
  - **空间线索（Spatial Cues）**：预测关键对象集合 O_key（与答案直接相关的对象）和提示对象集合 O_cue（可能与关键对象共现的周边对象），以增强对检测失败的鲁棒性。

### 2.4 评分式关键帧选择
- 对 LLM 选出的每个位置节点，根据其帧内检测节点中关键对象和提示对象的置信度加权聚合进行评分，选出该位置最富信息量的代表帧（关键对象与提示对象权重比为 10:1）；
- 共选出 k 帧，连同用户问题一并输入 VLM 进行最终回答。

### 2.5 算法流程（文字描述）
1. **离线/在线一次性构建**：在处理 3D 扫描视频时，同步接收 6-DoF 位姿和检测结果；当位姿变化超过阈值时，将缓冲帧形成新 LocNode；对每个位置内的检测轨迹生成 ObjNode；每帧检测作为 DetNode 挂载到对应 ObjNode 下。构建速度达 25+ FPS，单 GPU 实时运行。
2. **查询时**：LLM 读取序列化 MemTree3D → 输出 top-k 位置 + 空间线索 → 评分选出 k 个关键帧 → VLM 基于关键帧回答问题。
3. **多轮查询**：MemTree3D 构建一次后即可重复使用，后续查询无需重跑视觉模型，因此总延迟远低于视觉搜索方法。

## 6. 主要结论与发现

1. **MemTree3D 引导的关键帧选择能大幅提升 3D 问答准确率**：在相同输入帧数下，GPT-4o 的 LLM-Match 提升 17.4%，LLaVA-OneVision-7B 提升 5.8%，且优于现有最强的视觉搜索方法（VLM-Grounder、3D-Mem）。
2. **效率优势显著**：查询处理时间几乎不随视频长度增长，多轮查询场景下节省大量重复计算，符合具身场景实时交互需求。
3. **对感知失败具有鲁棒性**：当查询对象未在场景表示中出现时，仅损失 3.1 分 LLM-Match，远优于依赖视觉检测结果的现有方法。
4. **可扩展性强**：兼容闭源（GPT-4o）与开源（Qwen3 + LLaVA-OneVision）模型，开源模型组合甚至可超越均匀采样的闭源 VLM GPT-4o；构建过程单 GPU 实时运行，便于部署到具身智能体。
5. **场景规模影响增益幅度**：在大场景（HM3D，平均 556 m³）中增益（+24.6%）显著高于小场景（ScanNet，82.6 m³，+13.6%），表明方法在复杂大规模场景中价值最大。

## 7. 优点

- **范式创新**：突破传统“视觉搜索逐帧检索”的关键帧选择范式，提出“LLM 在场景表示上推理 → 按位置检索关键帧”的新思路，兼顾效率与准确率；
- **表示设计精良**：MemTree3D 采用三级树状结构，既能支撑 LLM 高层语义推理（LocNode + ObjNode），又保留细粒度检测信息（DetNode）用于评分选帧，实现了粗-细粒度信息的统一；
- **实时可构建**：利用 6-DoF 位姿而非语义聚类进行场景分割，避免额外视觉模型开销，支持 25+ FPS 在线构建，适合具身设备资源受限场景；
- **天然支持多轮对话**：场景表示一次构建、多次复用，多轮查询效率显著优于反复视觉搜索的方法；
- **鲁棒性机制**：LLM 时空线索（关键对象+提示对象）的设计减轻了对检测器精确度的依赖，在感知失败下仍能通过上下文关系推理合理位置；
- **实验严谨性**：统一阈值且不精心调参（1.5m/45°、权重 10:1），反映真实部署条件；对开源/闭源模型均做了验证，并公开代码。

## 8. 不足与局限

- **新颖对象定位固有短板**：当问题询问对象完全不存在于 MemTree3D 的 ObjNode 中且 LLM 缺乏先验位置线索时，仅靠“最合理猜测”常导致帧选择失败（作者在附录中明确承认此局限并给出失败案例）。
- **场景规模依赖**：在小场景（ScanNet）中性能增益相对有限（ScanQA/SQA3D 仅 +2.9%/+3.4%），方法优势主要体现在大型场景中。
- **检测器质量敏感**：虽然对漏检有一定鲁棒性，但 MemTree3D 构建高度依赖 YOLO-World 开放词表检测与 BoT-SORT 跟踪质量；检测类别覆盖面有限（仅 ScanNet-200 常见室内对象），对罕见或细粒度对象覆盖不足。
- **LLM 推理开销**：虽避免了视觉搜索，但每轮查询仍需 LLM 对整棵树（尤其是大场景中 LocNode 较多时）进行序列化读取与推理，OpenEQA HM3D 子集平均 20.3 个 LocNode，序列化长度可能成为瓶颈，论文未报告 LLM 查询本身的具体延迟。
- **实验覆盖与公平性**：算力支出未充分披露；未与更多近年 3D 场景图方法（如 SceneGraphFusion、OpenScene 等）对比；评分权重（10:1）和 k 值未做敏感性分析；部分消融仅报告单次结果，缺少方差统计。
- **评价指标局限**：OpenEQA 使用 GPT-4 LLM-Match 作为核心指标，受 GPT-4 评估器偏差影响；EM@1 指标无法反映答案语义部分的正确性。
