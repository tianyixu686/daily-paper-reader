## 摘要
针对长且相互关联的文档进行问答（QA）仍具挑战性，因为相关证据可能跨越多个实体及其关系。现有的检索增强生成（RAG）方法通常将文档索引为原始块，并通过嵌入相似性进行检索。当块边界将实体与支持证据分离，或问题需要跨语料库进行多跳推理时，其性能会下降。我们提出EnSI-RAG（实体结构索引检索增强生成），一种构建独立于查询的实体中心索引的框架。每条记录（e, t, k, v）表示一个实体e、其类型t、语义类别k（取值于{属性、关系、方面}）以及值v，同时保留对原始来源段落的链接。查询时，这些记录作为检索句柄，由LLM将检索到的段落综合为最终答案。该设计将证据定位与答案合成分离，同时保留可追踪的来源证据。在Loong和Oolong数据集上，EnSI-RAG实现了78.24的平均准确率。相对于用作参考的已发表基线分数，该结果高出6.62个百分点，表明其在这些设置下的有效性。代码可在https://github.com/RamonMeng/EnSI-RAG获取。

## Abstract
Question answering (QA) over long, connected documents remains challenging because relevant evidence may span multiple entities and their relationships. Existing retrieval-augmented generation (RAG) methods typically index documents as raw chunks and retrieve them through embedding similarity. Their performance degrades when chunk boundaries separate entities from supporting evidence or when a question requires multi-hop reasoning across the corpus. We propose EnSI-RAG (Entity-Structure-Indexed Retrieval-Augmented Generation), a framework that constructs a query-independent, entity-centered index. Each record (e, t, k, v) represents an entity e, its type t, a semantic category k in {property, relation, aspect}, and a value v, while retaining links to the original source passages. At query time, these records serve as retrieval handles, and an LLM synthesizes the retrieved passages into the final answer. This design separates evidence localization from answer synthesis while preserving traceable source evidence. Across Loong and Oolong, EnSI-RAG achieves an average accuracy of 78.24. Relative to the published baseline scores used as references, this is 6.62 points higher, suggesting its effectiveness across these settings. The code is available at https://github.com/RamonMeng/EnSI-RAG.

## 1. 核心问题与整体含义（研究动机与背景）

- 长文档问答中，证据往往分散在多个实体及其关系之间，例如金融跨报表比较、法律证据聚合、学术引用链追踪等，现有系统难以同时保留实体身份、文档结构和关系信息。
- 主流 RAG 方法将文档切分为固定长度 chunk，通过嵌入相似度检索；但块边界可能切断实体与其证据、分离表格行与表头、或将无关主题混入同一单元，导致检索结果局部相似却不足以回答问题。
- 长上下文 LLM 并非万能：即使扩展上下文窗口，模型仍存在“lost in the middle”现象，并且在高强度聚合和多跳推理问题上表现不佳。
- 现有图增强 RAG 多依赖短文本、实体规范化良好的场景，在长且异构的领域文档中假设往往失效。
- EnSI-RAG 的核心动机是：检索单元应依据语义而非机械长度来定义，并需要一种查询无关的实体结构索引来组织这些单元，从而将证据定位与答案合成分离。

## 2. 方法论

### 核心思想
- 构建独立的、查询无关的“实体中心”索引，每条记录为 `⟨e, t, k, v⟩`（实体、类型、语义类别、值），并链接回原始源段落。
- 结构化记录仅作为“检索句柄”，最终的答案生成仍基于原始证据文本，由 LLM 完成，从而实现证据定位与语义合成的分离。

### 离线预处理流程
- **Passage Construction（段落构建）**：将文档转换为以单一实体为中心的语义自包含段落，保留标题、表头、报告期、引用等局部结构上下文；段落长度不固定，按任务和文档类型动态设计，但都提供唯一 `psg_id` 并保持与源的关联。
- **Information Extraction（信息抽取）**：对每个段落抽取记录 `r = ⟨e, t, M, psg_id⟩`，其中 `M` 由字段 `m = ⟨c, k, v⟩` 组成，`c ∈ {property, relation, aspect}`：
  - property：属性/取值（如出生地）；
  - relation：与另一实体的关系（如引用）；
  - aspect：面向检索的信息方面（如方法、法律论证）。
  - 原则：每个索引字段必须有段落证据支持；抽取面向检索而非面向最终答案，允许部分记录存在，避免将抽取错误直接引入推理。
- **Index Entry Building（索引条目构建）**：将抽取结果转为 `[e][t][c: k = v] → {psg_id}` 的形式，同一键可对应多个段落 ID，保留证据的重复、矛盾或互补；为关系建立逆向条目（如 cites 对应 cited-by）；同时保留符号字段和文本表示，兼顾精确匹配与语义匹配。

### 在线问答流程
- **Retrieval Planning（检索规划）**：将用户问题转换为检索计划 `H(q) = {h1, ..., hm}`，每个 hop 可指定实体、实体类型、属性/关系/方面、值或目标实体；多跳时后续 hop 依赖于前面发现的结果。
- **Retrieval（检索）**：每个 hop 与索引键匹配，兼容性分数为：
  - `score(h, x) = Σ_{a∈{e,t,c,k,v}} λ_a · s_a(h, x)`
  - 其中 `s_a` 表示字段级匹配度，`λ_a` 控制贡献权重；
  - 通过候选集合合并：`C_h = ∪ I(x)`, `C_q = ∪ C_h`，去重后可重排序；
  - 支持部分约束、符号匹配与语义匹配组合，能够沿实体结构进行多跳跟踪。
- **Generation（生成）**：将检索到的原始段落直接提供给 LLM：`ŷ = LLM(q, C_q)`；不再进行额外索引或符号推理，只由 LLM 综合证据形成最终答案。

## 5. 主要发现与结论

### 关键结果摘要
- EnSI-RAG 在 Oolong 上比 SLIDERS 高 7.17 个百分点（71.84 vs 64.67），在 Loong 上高 6.07 个百分点（84.64 vs 78.57），平均提升 6.62 个百分点。
- 检索规划（Hop）加结构索引（Index）的组合增益最大：两者同时使用比仅用单一时提升超过 20 个百分点（消融实验中的绝对准确率从约 50% 提升至约 74%–80%）。
- 消融实验中，删除实体类型约束（`t`）影响最大（Loong Chain 下降8.4，Oolong 下降6.3），说明实体类型在约束检索语义边界方面起核心作用。
- 删除逆向关系条目在关系密集的 Chain 类任务上损失明显（7.3 分），但在其他任务上影响不大，印证了关系方向性在多跳推理中的重要性。

### 各子任务表现模式
- **Loong Spotlight**：不需要多跳的简单定位任务上，EnSI-RAG 与基线差距最小（约 3 分），说明结构化索引对简单任务仍有正向作用但幅度有限。
- **Loong Comparison**：实体级记录天然适合对比任务，因为每个实体属性被统一抽取、统一索引，检索时可以精确取回同一属性在不同实体上的取值。
- **Loong Chain**：受益于逆向条目和 hop 间依赖，EnSI-RAG 表现显著优于基线（约 9 分以上），验证了多跳关系追踪能力。
- **Loong Clustering**：通过实体、类型、属性的组合检索可以聚合具有共享属性的分散证据，其正确率提升接近 Comparison 任务。

### 对证据粒度与去重的分析
- 在相同召回条件下，检索到的内容大大减少，减少了 LLM 输入长度，通过将长文档分解为实体级记录，使模型能够在不超出上下文限制的情况下处理更广泛的证据。
- 在案例中，EnSI-RAG 能为多跳问题提取分散在多个段落中的证据，最终生成答案时不会出现 LLM 丢失关键线索的情况，而归一化块方法则受限于块间缺乏语义关联而无法做到这一点。
- 去重合并后的大约汇总证据集，实际喂给生成模型的内容通常少于总 token 预算，说明索引使检索更精准而非一味扩大召回。

## 6. 局限与潜在偏见

- **评估规模有限**：Loong 上的结果来自采样子集，非官方完整集合（177 个问题）；Oolong 也仅用了 192 个问题的合成子集，任务多样性有限。各基线分数来自其他论文，实验条件不完全一致。
- **预处理开销显著**：每次查询平均需要 157k 输入 tokens、468 秒离线构建时间和 32 次 LLM 调用，在实时应用场景中可能难以承受；虽查询无关的索引可以复用，但文档更新时需要全量重跑。
- **依赖商用 LLM**：信息抽取与检索规划、最终生成均依赖 OpenAI API（GPT-4.1-mini/GPT-4.1），存在封闭模型限制——API 升级或行为变化可能导致结果波动，并形成可复现性方面的障碍。
- **对结构化文档的假设**：EnSI-RAG 的抽取器假设文档可以被分割为以实体为核心的语义自包含段落，对语料库中相对正式的领域文档（金融报表、法律文书、学术论文）有效；对高度非结构化、口语化或实体边界模糊的文本（如聊天记录、口语转录）可能失效。
- **抽取错误的隐性传导**：尽管论文强调“面向检索的抽取允许部分记录存在”，但若预处理阶段漏抽或错抽关键属性，后续任何检索和生成环节都无法弥补；错误可能通过索引被放大而非自行纠正。
- **检索方案差异**：Loong Financial 中使用了本地嵌入模型（octen-embedding-8B），其他数据集则采用确定性切片选择，两种机制的检索难度不一致，跨数据集比较时需要考虑这一差异。
- **未报告模型间方差**：全文未给出多次运行的标准差或置信区间，单次运行的精度差异可能被过度解读。

## 7. 个人评价与思考

### 值得借鉴的贡献
- **“查询无关的实体级索引 + 查询时多跳规划”分离架构**是本文最突出的设计：它使索引构建成本可以一次性摊销，同时将检索规划从段落向量检索中解放出来，解决了基于块的 RAG 在多跳证据聚合上的核心痛点。
- **记录字段设计（property / relation / aspect）** 有较强的可迁移性：它不依赖特定领域的模式，而是提供了一种普适的抽取框架，新领域只需调整 Prompt 中的抽取指令。
- **证据保留原则（检索句柄与生成原文分离）** — 结构化信息只用于定位，不直接进入生成环节，避免抽取误差在最终答案中体现，是工程上很实用的折中设计。
- **逆向关系自动构建**虽然简单，但在实验中被证明对多跳推理十分重要，提示后续系统应重视关系的方向性和对称性处理。

### 可改进的方向
- **离线成本削减**：468 秒/查询的预处理速度严重限制其在动态文档场景的应用，可以用更轻量的抽取模型（如蒸馏后的 7B 级模型）或规则辅助的候选生成来缩减成本；也可引入增量索引更新。
- **自适应检索规划**：当前 hop 计划完全依赖 LLM 一次性生成，当规划本身错误时无法回溯；可引入检索后校验或“若检索失败则重新规划”的闭环机制。
- **评估统一化**：在不同子集上做跨论文比较仍缺乏严格性，建议在统一子集和同一组基线上做全面对比，并报告多次运行统计。
- **索引字段的时效性**：当实体属性随时间变化（如公司财报更新），旧的索引记录如何失效或替换未给出机制，这是现实部署需要考虑的问题。

总体而言，EnSI-RAG 通过“实体结构索引 + 多跳检索规划”给出了解决长文档多证据问答的一种新范式，其思想价值大于实现细节本身；但在工程成本、评估严谨性和领域泛化上仍有明显改进空间。
