## 摘要
检索增强生成（RAG）和大语言模型（LLM）的最新进展使研究人员能够将人工智能整合到科学工作流程中。然而，使用专有的商业人工智能系统引发了对于透明度、可复现性和隐私的担忧，而这些对于科学实践至关重要。为此，AquiLLM 被开发为一个使用开放权重模型的开源模块化 RAG-LLM 框架，旨在支持研究团队捕获隐性知识。在这项工作中，我们介绍了对 AquiLLM 的一系列架构改进和功能增强，包括本地嵌入和重排序、多模态能力、兼容 OpenAI 的推理接口、用户界面改进、语义和情景记忆能力以及技能支持。这些改进得益于与领域专家（包括天体物理学家和环境研究人员）的讨论，并代表着向更贴近科学研究实践的 AI 系统迈出的一步。

## Abstract
Recent advances in retrieval-augmented generation (RAG) and large language models (LLMs) enable researchers to integrate AI into scientific workflows. However, using proprietary commercial AI systems raises concerns about transparency, reproducibility and privacy, which are essential for scientific practices. To this end, AquiLLM was developed as an open-source modular RAG-LLM framework using open-weight models, designed to support research groups in capturing tacit knowledge. In this work, we present a series of architectural improvements and feature enhancements to AquiLLM, including local embedding and reranking, multimodal capabilities, OpenAI-compatible inference interfaces, user interface improvements, semantic and episodic memory capabilities, and skills support. These enhancements were informed by discussions with domain experts, including astrophysicists and environmental researchers, and represent a step toward AI systems more closely aligned with scientific research practices.

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：构建一个以**本地部署**和**模块化**为原则的 RAG-LLM 系统，将文档知识库与团队长期上下文（记忆）结合，并通过可配置的架构将隐性知识显式地编码到系统中。
- **关键技术细节**：
  - **模块化后端架构**：将原先单体代码库拆分为领域限定（domain-scoped）的独立应用模块，降低组件间耦合，使检索、编排、推理可独立迭代。
  - **本地嵌入与重排序**：用本地部署的 Qwen3-VL-Embedding-2B 与 Qwen3-VL-Reranker-2B 取代外部服务（如 Cohere），改善隐私保护与检索质量。
  - **OpenAI 兼容推理接口（vLLM）**：通过 vLLM 提供标准化调用接口，支持高效批量推理和 GPU 内存管理；同时以“sidecar”模型方式支持聊天、嵌入、重排序、语音转录等多类专用任务。
  - **多模态能力**：默认聊天模型 Qwen3.6-27B 支持文本与图像输入，可处理用户上传的图表；Whisper-large-v3-turbo 用于音频/视频转录，支持非正式材料（如会议录音）的入库。
  - **记忆层**：区分两类记忆策略：
    - *语义/用户记忆*：记录用户偏好、目标等长期稳定事实；
    - *情景记忆*：从过往对话中提取信息，支持相似度搜索与检索复用。
    - 记忆层默认关闭、可配置，依托 PostgreSQL + pgvector 实现，可选接入 Mem0 SDK，所有记忆数据均保留在本地。
  - **技能（Skills）与技能包（Skill Packs）**：将团队规范、操作规程（如数据还原检查表、标绘标准）以 Markdown 提示附加到特定项目集合，作为**程序性记忆**，使模型在对应会话中按团队规范解读资料。
  - **显著性感知的上下文打包（Salience-aware Context Packing）**：引入确定性 token 预算，按固定优先级（最新对话、工具链、关键用户回合等）进行分阶段剪枝；可选启用 LLMLingua-2 压缩低显著性内容，以在有限 GPU 资源下提升 token 效率与确定性。
  - **用户体验改进**：如 KaTeX 数学公式渲染、重构聊天界面、优化异步文件摄取流程（按文件并行处理）等。

### 7. 优点

- **架构设计的工程性**：模块化边界清晰，推理、检索、编排、内存彼此解耦，便于维护和独立演进；
- **本地化与隐私优先**：从嵌入、重排序到聊天推理全部可本地运行，不依赖商业 API，契合科研数据敏感场景；
- **对真实需求敏感**：改进方向来源于天体物理与环境科学领域专家的真实反馈，实用性强；
- **多模态覆盖**：支持文本、图像、音频/视频材料，能够摄入非正式和多样化科研资料，对隐性知识捕获尤为关键；
- **技能（程序性记忆）机制的创新性**：将团队规范以 Markdown 提示绑定到集合，无需修改系统核心代码即可实现“知识+使用方法”的捆绑传递；
- **内存层次设计的谨慎性**：默认关闭、可配置、fail-open 机制，反映出对隐私和错误风险的成熟考量；
- **上下文管理精细**：Token 预算、固定优先级剪枝、压缩与显式截断标记的设计，在有限计算资源下兼顾效率与可追溯性。

### 8. 不足与局限

- **实验覆盖不足**：缺乏对当前增强功能的端到端量化评测；未对非正式知识（会议记录、Slack 等）Tacit Knowledge 捕获效果进行验证；
- **跨领域泛化未证实**：评估集中于单一天体物理研究组，结论向其他学科推广需谨慎；
- **混合架构遗留问题**：代码库仍为“Django 页面 + React 岛屿”，与成熟消费级产品的交互体验仍有差距；本地与托管后端在流式输出、消息修剪等行为上存在不对称；
- **记忆一致性问题**：情景记忆异步写入、最终一致，短期可能产生刚发生的对话与记忆检索结果不匹配的情况；
- **部署复杂度较高**：诸多功能由配置开关控制，完全离线（air-gapped）部署需显式配置所有组件，系统复杂度对小型团队的能力要求较高；

- **检索与规模问题**：检索速度和扩展性随语料规模、计算资源与索引策略变化，尚未给出大规模场景下的实测数据；
- **基准方法论局限**：论文承认常规 LLM benchmark 不完全适用于科研场景，但目前也缺乏面向隐性知识捕获的专门评估范式。
