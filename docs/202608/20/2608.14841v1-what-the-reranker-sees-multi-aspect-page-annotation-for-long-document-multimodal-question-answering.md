## 摘要
针对包含文本、表格、图表和图形、长达数十至数百页文档的长文档视觉问答（VQA）通常采用先检索后阅读（retrieve-then-read）的流水线。在我们的设定中，瓶颈从检索召回转向重排序端的证据选择：在MMLongBench-Doc上，BGE-M3的Recall@20达到0.86，但F1@5仅为0.254；即便视觉检索器ColPali也仅达到F1@5=0.332；而一个仅见原始文本片段的纯文本重排序LLM，即使上游检索器已编码图像，也会遗漏表格、图表和版面证据。我们提出Trident，包含两个互补组件：Trident-R，一个与检索器无关的LLM重排序器，将每个候选转换为LLM可读的语义记录，包括视觉标题、章节路径、实体标签、多轴概念命中以及文本片段，然后执行一次自适应K的重排序调用；以及Trident-S，一个生成端模块，在综合前以主题、实体和结构视角提示VLM。在两个长文档数据集上，标注+重排序协议显著提高了五个异构池的检索F1，每个重排序后的池都超过了最强的自适应K基线PageIndex。没有标注的LLM重排序几乎不改变首位命中排名，表明提升来自结构化标注。Trident-S专门针对开放式综合问题设计，在这些问题上生成准确率最高可提升6.6个百分点。最佳Trident配置是我们评估中最强的下游问答流水线，两位LLM评判者的排名一致（kappa = 0.913）。

## Abstract
Long-document visual question answering (VQA) over documents of tens to hundreds of pages mixing text, tables, charts, and figures typically follows retrieve-then-read pipelines. In our setting, the bottleneck shifts from retrieval recall to reranker-side evidence selection: on MMLongBench-Doc, BGE-M3 reaches Recall@20 = 0.86 but only F1@5 = 0.254, and even the visual retriever ColPali reaches only F1@5 = 0.332; a text-only rerank LLM seeing only raw snippets misses table, chart, and layout evidence even when the upstream retriever encoded images. We propose Trident, with two complementary components: Trident-R, a retriever-agnostic LLM reranker that converts each candidate into an LLM-readable semantic record, including a visual caption, section path, entity tags, multi-axis concept hits, and a text snippet, then performs a single adaptive-K rerank call; and Trident-S, a generation-side module that prompts the VLM under topical, entity, and structural lenses before synthesis. On two long-document datasets, the annotation+rerank protocol substantially improves retrieval F1 across five heterogeneous pools, with every reranked pool exceeding the strongest adaptive-K baseline PageIndex. An LLM rerank without the annotation barely changes first-hit ranking, indicating the lift comes from the structured annotation. Trident-S targets open-ended synthesis questions by design, adding up to 6.6 points in generation accuracy on these questions. The best Trident configuration is the strongest downstream QA pipeline in our evaluation, with rankings consistent across two LLM judges (kappa = 0.913).

## 2. 论文提出的方法论

论文提出 **TRIDENT** 框架，由两个互补组件构成：

### 2.1 TRIDENT-R：证据选择（检索端）
核心思想：将候选页转换为“LLM 可读的语义记录”，再执行自适应 K 的 LLM 重排。

**（a）TRIDENT-R-Index：多方面页面标注**
- 概念集 `C = C_T ∪ C_E ∪ C_S`，分为三个正交轴：
  - **主题概念（C_T）**：将每页切分为 ≤512 token 的重叠窗口，用句嵌入模型编码后做 mini-batch K-means 聚类（K_T = min(64, |W|/8)），每个聚类成为一个主题概念，记录概念-页面权重；
  - **实体束概念（C_E）**：LLM 提取每页命名实体、数字、日期、货币、百分比等，基于共现关系做密度聚类，形成实体束；
  - **结构概念（C_S）**：用 PDF 结构解析器（PageIndex API）获取章节树，每个叶子章节作为一个结构概念。
- 每页附加四类元数据：结构路径字符串、视觉标题（VLM 以 ≤60 词描述页面的表格/图形/版面）、实体标签列表（top-15）、文本片段（600 字符截断）。

**（b）自适应-K 重排**
- 对每个候选页组装结构化记录 `R_p = (p, s_p, ch_p, M_p)`，包括检索器得分、概念命中列表（≤6 个 T/E/S 标签）、以及上述四类元数据；
- 将全部候选序列化为 JSON 列表，以单次 LLM 调用（τ=0）返回自适应 K≤5 的有序页面子集；
- 重排器可返回少于 K_max 的页面（证据集中时），实现自适应选择。

### 2.2 TRIDENT-S：多视角生成（生成端）
- 对同一组检索到的页面图像，并行发起三次 VLM 调用，分别从三个视角提取答案：
  - **主题视角（T）**：每页的主题内容，哪些主题与问题相关；
  - **实体/数值视角（E）**：逐字提取页面上的命名实体、数值、日期、表格单元格、图形标签；
  - **结构视角（S）**：每页在文档组织中的位置（章节标题、页眉、图表标题）。
- 第四次合成调用将三视角答案合并为最终答案，并附带格式感知偏好（数值问题倾向 E 视角、位置问题倾向 S 视角、共识优先）。
- 三视角均判定不可回答时，返回 “Not answerable”。

### 2.3 XKG 多轴候选池（可选检索器）
- 通过轻量 LLM 路由器将问题分类为 {topical, entity-level, structural, mixed} 四类；
- 按类条件融合权重（α_T, α_E, α_S）聚合成页面级分数：
  `s_p(q) = Σ_X α_X^κ · Σ_c score_X(c, q) · w_{c,p}`

## 6. 论文的主要结论与发现

1. **重排序接口是长文档 VQA 的关键瓶颈**：上下文的证据页通常已在 top-20 池中（Recall@20=0.86），失败发生在证据子集的甄别环节；
2. **结构化标注 + LLM 重排显著有效**：同一标注+重排协议将五个异构池的 F1 平均大幅提升（如 BGE-M3：0.254→0.546；ColPali：0.332→0.581），且均超过强自适应 K 基线 PageIndex（最优 F1 为 0.581）；
3. **提升来自结构化标注而非 LLM 重排本身**：仅用文本片段的重排对 MRR 几乎无改善（BGE-M3：0.524→0.523），在 ColPali 上甚至下降（0.692→0.598）；
4. **视觉标题是最关键的标注字段**：仅保留视觉标题即可恢复完整标注约 90% 的提升（两个池上均 −0.028/−0.027，高度池无关）；移除视觉标题在 BGE-M3 上损失更大（−0.130 vs ColPali 上 −0.083），说明视觉标题不仅是文本检索器的模态补全，更是重排序器的通用语义接口；
5. **TRIDENT-S 只在开放式综合问题上有效**：在开放题上带来 +1.7 至 +6.6 的 Gen Acc 提升，但在 MCQ 和短抽取式问题上几乎无增益（各视角收敛到相同答案，合成调用被绕过）；
6. **最佳配置**：ColPali + 标注 + 重排 + TRIDENT-S 是最强下游流水线（Gen Acc 53.7%，Gen F1 48.9%），且两位独立 LLM 评判者的排名一致（κ=0.913）。

## 7. 优点

- **问题定义精准**：准确定位了长文档 VQA 中“检索已够好、重排是瓶颈”这一被忽视的问题，并通过实验数据（Recall@20 与 F1@5 的巨大落差）清晰论证；
- **方法设计简洁高效**：将计算密集的多模态理解移到离线索引阶段（每文档一次），在线仅需一次 LLM 重排调用，避免了多模态 LLM 每次重排都处理图像的高成本；
- **训练无关（training-free）且检索器无关**：不需要端到端训练或 RL，可即插即用到任何现有流水线；五池隔离实验有力证明了这一普适性；
- **消融设计严谨**：通过“文本片段 vs 仅标题 vs 完整标注”的机制对比，直接定位了性能提升的来源（结构化标注尤其是视觉标题），而非笼统归因于“加了 LLM 就会更好”；
- **透明与诚实**：明确区分了 TRIDENT-S 的适用场景（开放题有效、抽取题无效），而非宣称普适提升；公开了成本核算、子集采样偏置分析、标题泄漏审计、双评判者一致性等辅助证据；
- **审计意识强**：对 VLM 生成的视觉标题做了泄漏审计（0% bigram 匹配），证明提升不是答案泄漏的假象。

## 8. 不足与局限

- **对专有模型的依赖**：所有核心 LLM/VLM 组件均使用 GPT-4.1/GPT-4o-mini，论文未验证较小或开源模型的替代效果（仅作为 future work 提及），实际部署可能受限于 API 成本和模型可用性；
- **端到端评测规模有限**：300-QA 子集统计功效不足，顶级流水线之间的差异未达显著性阈值（p<0.05）；该子集在文档长度上偏离原始分布（偏向长文档），不能完全代表全集；
- **离线索引成本不可忽略**：每 100 页约 $0.256 的索引成本，虽可分摊到多次查询，但对于一次性或低频查询场景，该成本可能高于收益；
- **视觉标题的泄漏风险未完全排除**：9.2% 的标题包含金标准答案的精确子串，论文论证这是“正确编码视觉内容的预期行为”而非泄漏，但这一界限可能因数据集而模糊；
- **PageIndex 基线比较的公平性**：PageIndex 输出的是章节节点而非页面，需要展开并截断到 top-5 才能对齐比较，这一后处理可能削弱其性能（尤其在 LongDocURL 上 49.7% 的查询触发截断）；
- **LongDocURL 上的验证不够全面**：完整五池隔离仅在 MMLongBench-Doc 上进行，LongDocURL 只作为外部迁移检查，未对全部池配置进行验证；
- **结构解析器的依赖**：使用 PageIndex API 作为 PDF 结构解析器，虽然可替换（PyMuPDF、GROBID），但未做解析器替换的鲁棒性研究；
- **人类评测缺失**：端到端质量依赖 LLM-as-judge（虽然双评判者一致性很高 κ=0.913），论文也承认未进行人类评测（评估规模为 14×300=4,200 对预测-金标）。
