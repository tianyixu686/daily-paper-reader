## 摘要
多跳检索必须恢复能够共同提供足够证据的段落。初始段落通常解析问题中隐含的实体或关系，使得缺失的证据只有在检索开始后才更容易描述。图检索通过存储的语料库结构改善了相关证据的获取，但其检索信号通常源自原始问题。因此，即使观察到的段落提供了更直接的语义线索，互补的证据也必须通过存储的关系来获取。我们引入了EviReform，将检索请求的修订与图中证据的聚合分离开来。检索到的源段落为未解决的信息需求制定了残余查询。原始和残余检索信号分别归一化、组合，并在共享实体的命题之间传播。在2WikiMultiHopQA、HotpotQA和MuSiQue上，EviReform比最强基线高出最多5.59个Recall@5点和4.50个F1点。这些结果表明，观察到的证据可以引导图检索朝着原始问题未明确指出的支持链部分进行。代码可在https://github.com/XrazyMee/EviReform获取。

## Abstract
Multi-hop retrieval must recover passages that provide sufficient evidence together. An initial passage often resolves an entity or relation implicit in the question, making the missing evidence easier to describe only after retrieval begins. Graph retrieval improves access to related evidence through stored corpus structure, but its retrieval signal is commonly derived from the original question. Complementary evidence must then be reached through stored relations even when an observed passage provides a more direct semantic cue. We introduce EviReform, which separates revising the retrieval request from aggregating evidence in the graph. Retrieved source passages formulate residual queries for the unresolved information need. The original and residual retrieval signals are normalized separately, combined, and propagated between propositions that share entities. On 2WikiMultiHopQA, HotpotQA, and MuSiQue, EviReform exceeds the strongest baseline by up to 5.59 Recall@5 points and 4.50 F1 points. These results show that observed evidence can guide graph retrieval toward the part of a supporting chain left underspecified by the original question. Code is available at https://github.com/XrazyMee/EviReform.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：多跳问答中的检索任务不能仅依赖原始问题作为检索信号。在多跳场景下，一个初始检索到的段落往往会解析出问题中隐含的实体或关系，使得“剩余缺失的证据”只有在看到该段落后才变得容易描述。然而，现有图检索系统（GraphRAG）的种子、路径或边权重通常仍固定于原始问题，无法利用已观察段落提供的更直接语义线索来引导后续检索。
- **背景**：图检索（GraphRAG）通过存储在语料库中的结构（实体、命题、段落关系）提升互补证据的获取，但它的检索信号一般来自原始问题。因此，当互补证据涉及隐含桥接（implicit bridge）时，系统只能通过图中已存储的关系间接到达，过程低效且容易丢失。
- **整体含义**：论文主张将两个常被混在一起的操作分开——**检索请求的修订**和**图内证据的聚合**。即：检索前用原始问题决定图入口；检索后用观察到的段落内容重新表述新的信息需求；两者互补，不可互相替代。更好的图遍历并不能替代基于证据的查询修正，反之亦然。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想
- **EviReform** 将检索信号分为两个通道：
  1. **原始问题通道**：由原始问题产生的命题检索种子；
  2. **残差查询通道**：根据初始观察到的源段落（evidence）生成的多个“残差查询”（residual queries），用于描述尚未解决的信息需求。
- 两个通道的信号分别归一化后按权重组合，再经过共享实体传播，最终统一输出一个段落排序。

### 2.2 技术流程与公式
1. **命题-实体索引构建**
   - 用 LLM 将每个段落分解为自包含命题（propositions），并抽取实体；
   - 记录命题到源段落的归属映射 `π(i)`；
   - 构建命题-实体稀疏关联矩阵 `A ∈ {0,1}^{M×Ne}`。

2. **初始证据选择**
   - 用原始问题 `q` 的嵌入对命题打分：`u_i(q) = max(0, h_i^T h_q)`；
   - 由 LLM 从最高分候选中选出至多 12 个命题 `S_q`，作为入口命题；
   - 这些命题的得分构成原始种子 `b`（归一化为单位 L1 范数）；
   - 这些命题的完整源段落组成“已观察证据” `E_q`。

3. **查询重构（Query Reformulation）**
   - 将 `(q, E_q)` 交给 LLM，生成最多 3 个残差查询 `ρ = {ρ1, ..., ρL}`；
   - 每个残差查询独立检索命题，得到归一化信号 `r^(ℓ)`；
   - 对所有有效残差信号求平均，得到 `r`。

4. **信号组合**
   - 组合公式：`s = βb + (1-β)r`，其中 β=0.5 为默认值；
   - 若残差查询均无效，则 `s = b`；
   - 分离归一化避免了残差数量或量纲压倒原始问题。

5. **共享实体传播（Graph Propagation）**
   - 构造命题间转移矩阵 `T = W D_w^{-1}`（W 通过实体共享构建）；
   - 一次传播更新：`z = αs + (1-α)Ts`，α=0.5。

6. **段落读出**
   - 将命题得分聚合到源段落：`score(d_j) = (1/√|P_j|) Σ z_i`；
   - 按此得分排序，返回 Top-K 段落。

### 2.3 算法流程（文字版）
1. 用原始问题检索命题；
2. 选择入口命题，得到其源段落作为观察证据；
3. 由 (q, E_q) 生成残差查询；
4. 残差查询独立检索命题，得到残差信号；
5. 将原始种子与残差信号按 β 混合；
6. 在共享实体图上执行一步传播；
7. 将命题得分聚合到段落，输出最终 Top-K 段落排序。

## 6. 论文的主要结论与发现

- **EviReform 显著优于现有最强基线**：
  - R@5 在 2Wiki、HotpotQA、MuSiQue 上分别提升 5.00、2.65、5.59 点；

- **完整支持链恢复（Chain@5）提升巨大**：比最强图基线高 22.5、12.1、11.7 点，说明原始问题往往只能到达一个入口段落，而观察到的段落能指明缺失的互补证据。
- **机制分析**：
  - 查询重构贡献最大，图传播带来稳定但较小的增益；
  - 使用残差查询而非重复原始问题，是效果提升的关键；
  - 重排初始候选池无法替代残差检索：初始池中完整链覆盖率远低于扩展池。
- **结论**：观察到的证据可以引导图检索到原始问题未明确表述的支持链部分，证据引导的查询重构是多跳图检索的有效补充而非替代。

## 8. 不足与局限

- **实验覆盖有限**：仅使用三个英文多跳 QA 数据集和一个医疗数据集，且每个数据集只构造了一个索引，未涉及其他语言或更广泛的领域。
- **LLM 依赖导致不确定性**：索引构建、命题选择、查询重构都依赖 LLM 输出；论文承认没有评估索引重建或 LLM 推理重复带来的变化，bootstrap 区间仅覆盖问题抽样变化。
- **MuSiQue 上的最终排序仍难**：残差检索扩展了覆盖，但完整链覆盖率与最终 Chain@5 之间仍存在较大差距（14.8 点），说明“找到证据”和“选择紧凑证据集”是两个仍需解决的问题。
- **医疗基准不可比**：GraphRAG-Bench (Medical) 缺乏金标段落，只能通过答案质量间接评估，不能直接用于检索指标对比。
- **成本未完全透明**：虽然给出了 token 数和耗时，但未提供端到端的总算力/时间，难以评估实际部署成本。
- **单次运行**：所有方法每个数据集只运行一次，缺少多次运行以衡量方差。
