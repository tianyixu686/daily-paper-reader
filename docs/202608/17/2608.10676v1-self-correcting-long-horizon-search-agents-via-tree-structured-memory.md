## 摘要
基于大语言模型（LLM）的搜索智能体通过与外部环境的多步交互来回答问题。然而，将完整的执行轨迹提供给LLM会导致上下文无限增长并引入噪声。现有的压缩方法以牺牲重要细节为代价来缩减上下文，并且常常在替换错误事实时，未能修复源自这些错误事实的下游推理。为解决这一问题，我们提出ReTree，一种用于搜索智能体的自我修正树状结构记忆机制。ReTree构建有界的分步推理上下文，同时保留基于来源的证据链接。它将搜索建模为证据树，树中的节点存储有界摘要、证据和修订历史。当新检索到的证据与先前声明矛盾时，ReTree回溯到引入该声明的节点，替换过时证据，重新生成摘要，剪除受影响的支路，并恢复搜索。基于来源的证据溯源支持可靠的冲突定位，并使最终声明可追溯到检索到的段落。在四个公开的问答和搜索基准上的实验表明，ReTree始终优于完整轨迹ReAct，回答准确率最高提升25.6个百分点（pp）；完整轨迹ReAct的平均最大每步推理上下文是ReTree的$1.27$--$1.51$倍。这些结果确立了ReTree作为长时程搜索的有效自我修正记忆抽象。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

## 1. 论文的核心问题与整体含义（研究动机与背景）

基于大语言模型（LLM）的搜索智能体通过多步检索与外部环境交互来回答知识密集或多跳问题。该类系统面临两个相互交织的核心挑战：

- **上下文无界增长**：若将完整执行轨迹（全部查询、观察、中间结论）输入策略模型，每步推理上下文随搜索轮次线性增长，导致计算开销增大、噪声累积。
- **错误级联（Error Cascade）**：检索本身可能引入过时、无关或冲突的信息。由于后续查询和中间结论都依赖于当前状态，一个错误前提会同时污染后续检索方向和证据解读方式，形成级联错误。

现有方法（如滚动摘要、报告重构、观察掩蔽等）虽能压缩上下文，但存在两类关键缺陷：一是压缩会丢失来源级证据细节；二是当新证据修正了原始错误事实后，基于该事实推导出的下游结论仍被保留，系统缺乏“依赖一致性”的修复能力。

**ReTree 的核心命题**：搜索智能体的工作记忆不应只是“更短的转录文本”，而应当是**可编辑的状态表征**。它需要同时满足三个联合要求：有界的分步推理上下文（Bounded Context）、声明到来源的可追溯性（Traceability）、依赖一致的修正机制（Dependency-Consistent Revision）。ReTree 借鉴真值维护系统（Truth Maintenance System, TMS）的依赖定向修正思想，将其实例化到 LLM 搜索循环中，为长时程搜索提供了一种新的记忆抽象范式。

## 2. 论文提出的方法论

### 2.1 核心思想

ReTree 将搜索过程建模为一棵**证据树（Evidence Tree）**。树中的节点不是候选推理路径，而是随搜索推进而演化的**状态节点**：一条边表示子节点状态是由父节点的活跃证据派生而来的。每个节点存储三部分内容：

- **有界摘要 sₙ**：紧凑的任务状态摘要，记录已解析的答案槽、中间槽、剩余开放槽和未解析候选，最多 140 词。
- **局部证据 Eₙ**：在该节点新引入的原子事实（atomic evidence），每个事实带有稳定标识符和来源 URL。
- **修订历史 Hₙ**：该节点发生过的证据替换记录。

### 2.2 关键技术细节

**（1）有界上下文构建（公式 7）**

`Cᵏ(Mₜ, q) = sₙₜ ∥ TopKₖ(A(nₜ), q ∥ sₙₜ)`

每个搜索步骤，策略只看到当前活跃节点的摘要加上 top-5 个词法相关证据项。由于摘要和原子证据均有界，每步推理上下文复杂度为 O(1)，与轨迹长度无关。

**（2）证据提取与源绑定**

检索到的段落通过提取器生成最多 6 条原子事实，并通过**段落索引绑定**（passage-index binding）锚定来源。这种方法避免了让 LLM 直接复述 URL（后者可能产生不可验证的虚假引用），保证事实来源可核验。

**（3）矛盾触发的回溯修正（核心机制）**

- **冲突检测**：新证据与已有事实比较，仅在满足“同实体、同属性、同scope、同时间，但取值不兼容”时才提议回溯。不同实体义、细化说明、竞争但兼容的候选仅扩展树结构。
- **历史感知确认**：第二层判断器接收分支摘要、目标事实变更历史等，防止同一值被反复翻转造成振荡。
- **结构化修复**：一旦冲突确认，定位引入被反驳事实的节点 ι(j)，替换该事实文本与来源，追加修订记录，仅从修正后的累积证据重新生成该节点摘要，然后**剪除其所有后代节点**，从修复节点恢复搜索。
- **剪枝策略**：以祖先关系作为语义依赖的保守代理，优先保证修复安全而非保留可能有效的状态。

**（4）声明级归因（公式 8）**

最终答案生成器将推理分解为原子声明，每个声明映射到证据 ID，再经证据映射解析到当前证据文本和 URL，最终回溯到原始检索段落。通过 NLI 判断器验证引用段落与声明之间的蕴含关系。

## 8. 不足与局限

- **硬剪枝策略可能过度失效**：将祖先关系作为依赖的保守近似，会删除实际上与被修正前提无关的后代事实，导致有用状态丢失。论文承认这是“安全性优先”的取舍，但代价是冗余重检索和重建。
- **依赖冲突判断器质量**：假阴性（漏判冲突）会保留污染证据，假阳性（误报冲突）会导致过度剪枝。尽管同范围规则和历史确认降低了两类错误，但并未消除。
- **外部存储无界增长**：虽然每步推理上下文有界，但总证据存储仍随检索持续增长，词法 top-k 选择和树遍历均为线性复杂度，超长时程下操作延迟会上升。
- **计算开销**：结构修复需要额外的 LLM 调用，相对 FlatUpdate 多 7–11% 调用和 10–13% token，长时程大规模部署时成本需进一步优化。
- **评估局限**：主实验仅使用单一 8B 模型，无法判断方法在大模型上的收益；基线覆盖不够齐全；未涉及多轮不同问题之间的长期记忆场景（ReTree 被定位为单次搜索任务的工作记忆而非通用长期记忆）。
- **实现层面**：词法 top-k 证据选择忽略了语义相关性；未使用向量索引和缓存，存在明显性能优化空间。
