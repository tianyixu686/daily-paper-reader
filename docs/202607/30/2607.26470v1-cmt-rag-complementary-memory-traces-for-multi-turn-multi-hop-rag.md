## 摘要
多轮信息寻求对话需要跨轮次的多跳推理和长距离依赖追踪。然而，现有的RAG系统通常将对话记忆表示为原始对话历史、重写查询或非结构化摘要，这使得难以恢复后续查询所需的特定先前推理步骤和证据。我们的关键洞察是，通过将对话上下文表示为子问题级推理痕迹，使对话记忆与检索对齐。基于这一洞察，我们引入了MuMu-QA，一个带有显式跨轮次子问题依赖注释的多轮多跳RAG基准，以及CMT-RAG，一种针对该设置的互补记忆框架。在每一轮中，CMT-RAG采用状态空间痕迹生成器，其循环状态作为运行时记忆，以整合最近的对话上下文并将当前查询分解为包含面向检索的子问题和与先前痕迹依赖关系的结构化痕迹草稿。然后它用检索到的证据对这些草稿进行接地，并将其作为持久记忆痕迹存储在会话级DAG中，使未来轮次能够有效恢复相关的先前推理和证据。在MuMu-QA和语料级RAG基准上的实验表明，CMT-RAG在答案准确性上持续优于五类RAG基线。

## Abstract
Multi-turn information-seeking conversations require both multi-hop reasoning and long-range dependency tracking across turns. However, existing RAG systems typically represent conversational memory as raw dialogue history, rewritten queries, or unstructured summaries, making it difficult to recover the specific prior reasoning steps and evidence required for follow-up queries. Our key insight is to align conversational memory with retrieval by representing dialogue context as sub-question-level reasoning traces. Building on this insight, we introduce MuMu-QA, a benchmark for multi-turn multi-hop RAG with explicit cross-turn sub-question dependency annotations, and CMT-RAG, a complementary memory framework for this setting. At each turn, CMT-RAG employs a state-space trace generator, whose recurrent state serves as runtime memory, to incorporate recent conversational context and decompose the current query into structured trace drafts containing retrieval-oriented sub-questions and dependencies on earlier traces. It then grounds these drafts with retrieved evidence and stores them as persistent memory traces in a session-level DAG, enabling future turns to efficiently recover relevant prior reasoning and evidence. Experiments on MuMu-QA and corpus-level RAG benchmarks show that CMT-RAG consistently outperforms five categories of RAG baselines in answer accuracy.

## 2. 方法论：核心思想、关键技术细节、算法流程
### 2.1 核心思想
- **互补记忆架构**：  
  - **运行时记忆**：状态空间模型（SSM，基于Mamba-2）的循环状态，携带局部对话上下文（话题焦点、意图转移、表层共指）。  
  - **持久化记忆**：会话级有向无环图（DAG）存储已完成轨迹，每个轨迹绑定子问题、关键词、依赖边和本地检索的段落ID。
- **轨迹单元**：将每个检索级子问题封装为`(sub-question, keywords, deps, para_ids)`，使记忆单元与检索单元一致。

### 2.2 关键技术细节
- **状态空间轨迹生成器**（TraceGen）：  
  - 使用Mamba-2（2.7B参数）作为骨干，其选择性状态空间混合器维护循环状态`h_t`，避免重复编码全对话历史，减轻“lost-in-the-middle”效应。  
  - 通过LoRA微调和直接偏好优化（DPO）训练，生成的轨迹草稿包括：分解子问题`qdecom_k`、检索关键词`kw_k`、依赖前置轨迹ID列表`deps(k)`。
- **轨迹DAG管理**：  
  - 对于每个草稿，先解决引用依赖（将子问题中的`[A_k]`替换为对应答案），得到解析后的子问题`qsub_k`。  
  - 两种证据检索：  
    - 依赖边直接复用前置轨迹的证据（`Pprior_k`）。  
    - 关键词通过轻量词法匹配在DAG中查找相关历史轨迹，并获取其段落ID。  
    - 同时从外部语料库用`qsub_k`进行密集检索（DRAGON）获得`Plocal_k`。  
  - 合并去重后形成最终段落集`P_k`，传递给无状态读者回答。
- **训练方法**：  
  - **三阶段课程SFT**：  
    - Stage1：单轮示例学习轨迹语法和分解结构。  
    - Stage2：短多轮对话（3-7轮）。  
    - Stage3：长多轮对话（6-32轮），同时回放部分Stage2示例。  
  - **DPO训练**：从Stage3策略中采样4个候选轨迹，通过固定检索-读者管道执行，使用最终答案F1和匹配子问题F1的复合奖励排序，构建偏好对进行DPO。
- **推理流程**（Algorithm 1）：  
  1. SSM生成轨迹草稿集和更新状态。  
  2. 解析依赖引用，执行DAG关键词查找和密集检索。  
  3. 读者（无状态）分别回答每个子问题，聚合后输出最终答案。  
  4. 将完成轨迹追加到DAG，状态和DAG传递至下一轮。

## 8. 不足与局限
- **依赖分解准确性**：CMT-RAG性能严重依赖轨迹生成器的子问题分解和依赖预测精度。若分解错误，后续证据聚合会失败（Oracle轨迹实验显示仍有约0.6-3.3 F1提升空间）。  
- **数据集局限**：MuMu-QA是基于MuSiQue合成构建，继承了其**领域偏差**和合成性（非人类自然对话），可能导致在真实多轮对话中泛化性存疑。作者也指出未来需要人工作者对话进行验证。  
- **实验覆盖不足**：  
  - 仅评估两个读者（Qwen3-32B和Llama-3.3-70B），未测试更大模型或不同部署场景。  
  - 超长对话（33-67轮）仅用于评估，未进行训练，且记忆通道消融在该区间仅有200个对话，统计稳定性可能不足。  
- **应用限制**：轨迹DAG需在会话内存中维护，对于极长对话（数百轮）内存和检索开销可能上升；关键词匹配依赖人工设定阈值（0.05），缺乏自适应性。  
- **对比方法处理**：部分基线（如LogicRAG、ChainRAG）本为非对话设计，作者通过重放历史使其适应多轮，但在原始场景中表现可能更优。此外，所有基线均未使用DPO或类似强化学习，比较不完全公平。
